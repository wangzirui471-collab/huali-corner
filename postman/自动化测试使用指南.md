# 转角 · 接口自动化测试 —— 使用指南（可存储版）

> 一句话：本项目已把所有接口做成 **Postman 集合 + Newman 命令行 + GitHub Actions 三件套**，
> 以后想跑接口回归测试，有三条路：**Postman 界面点 Run** / **双击一键脚本** / **push 自动跑**。
> 本文档就是给你存着、下次照着做就能跑通的完整说明。

---

## 0. 先记住三件事（最重要）

1. **集合有两份并存**：`*.postman_collection.json`（Newman / CI 用，2.1 格式）+ `collections/*/`（Postman 12 界面用，3.0 目录树）。**不要手改 `collections/` 下的 yaml**，它由脚本生成，会整体重建。
2. **`tools/gen_all_apis.py` 是主站集合的唯一源头**：接口变了先改它，再重新生成。手改 json 或 yaml 都会被覆盖。
3. **测试会写数据，必须配临时数据目录 / 试用模式跑**，绝不碰你平时用的真实数据和 `var-trial/`。一键脚本已经帮你做好了隔离。

当前实测结果：**145 请求 / 442 断言 / 0 失败，全绿 ✅**（主站 130/388 + AI 14/50 + FAQ 数据驱动 1 组/4 断言）。

## 1. 怎么开始自动化接口测试（三种方式，挑一种）

### 方式一：Postman 软件界面里点 Run（最直观，适合手验）

前提：本地的后端和 AI 服务已经起好（见第 3 节）。

1. 打开 Postman 12 → 左侧应出现三套集合（`转角主站-全接口`、`转角AI客服`、`转角AI客服-数据驱动回归`）。
   它监听文件变化；没出现就 `File → Open Folder` 选一次 `huali-corner-trial` 仓库根目录。
2. 右上角环境选择器选 **「转角」**（`baseUrl` 已填 `http://127.0.0.1:8081`；AI 集合用「转角-AI客服-8093」环境）。
3. 在集合上点 **Run → Run**，跑整条链路（请求按 order 顺序执行，token 靠前置请求写入集合变量）。
4. **不要只点单个请求的 Send**——token 是「00 · 准备」里登录请求写进变量的，单独发一个必 401。

> 为什么之前在软件里看不到集合？因为 Postman 12 的「打开文件夹」只认 3.0 目录树，不认 2.1 单文件 json。
> 现在 `collections/` 目录树就是给界面看的，已生成好。

### 方式二：本地一键脚本（推荐，30 秒跑完三套）

**双击 `postman\一键跑测试.bat`** 即可。它会自己：
起 AI 服务（8094）+ 后端（8095，临时数据目录）→ 探活 → 依次跑三套集合 →
生成 `postman\运行报告.md` → **关掉刚才起的两个服务**（不碰你的 8081/8093 和 var-trial/）。

命令行等价写法（Windows，用项目虚拟环境，里面有 Pillow）：

```powershell
"E:\zi\huali-corner-trial\.venv-trial\Scripts\python.exe" postman\run_all.py
```

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--keep` | 跑完不关服务，留着手动调（会打印端口） |
| `--only api` | 只跑某套，可选 `api` / `ai` / `faq`，可写多个，如 `--only api faq` |
| `--api-port N` / `--ai-port N` | 换端口，默认 8095 / 8094（刻意避开日常用的 8081 / 8093） |
| `--newman "命令"` | newman 找不到时手动指定；默认 PATH → WorkBuddy 自带 → npx |

退出码：**全绿 0，有失败 1，服务没起来 2**（可直接挂到任何 CI）。

### 方式三：GitHub Actions（push / PR 自动跑，零配置）

工作流已写好：`.github/workflows/postman-api-tests.yml`。触发条件：
push 到 `main/master/develop/feature/**`、开 PR、或手动 `workflow_dispatch`（可勾选跳过 AI 集合）。

它在干净的 Linux 容器里：装依赖 → 起 AI 服务（8093，`HC_AI_MOCK=1`，先 `ingest.py` 现造索引）→
起后端（8081，`--trial --no-seed` + 临时数据目录）→ 探活通过后跑 Newman，失败就让 CI 变红。
**AI 链路走 mock，不联网、不花钱、不需要配任何 Secret 即可跑。** 报告作为 artifact 上传。

## 4. 改动怎么同步（核心规则）

接口变了，正确流程：

1. 改 `postman/tools/gen_all_apis.py` 里的 `ITEMS` 表（一行 = 一个请求：分组、名称、方法、路径、query、body、预期状态码、用哪个 token、要提取哪些变量）。
2. 跑 `python postman/tools/gen_all_apis.py` → 重新生成 `转角主站-全接口.postman_collection.json`。
3. 跑 `python postman/tools/to_postman_files.py` → 重新生成 `collections/转角主站-全接口/` 目录树（界面同步更新）。
4. 跑一轮 newman 校准预期状态码。

**反规则**：
- 别手改 `collections/` 下的 yaml（转换会整体重建，手改被覆盖）。
- 别手改 `*.postman_collection.json` 当长期维护方式（json 和 yaml 互不自动同步，容易跑旧版）。
- 在 Postman 界面里临时改的请求只写进 yaml，不会回写 json——所以把 `gen_all_apis.py` 当唯一真相源。

> 双格式并存原因：Newman（CI）认 2.1 单文件 json，Postman 12 界面认 3.0 目录树，两者格式不互通，所以由 `to_postman_files.py` 从 json 派生 yaml。

## 5. 已知坑与约束

| 现象 / 约束 | 原因 / 处理 |
| --- | --- |
| `401` + `{"error":"请先登录"}` | 路径写错了。`/api/user/login` **不存在**，正确的是 `/api/auth/login`。未知路径被兜底鉴权当「未登录」返回 401。 |
| `Cannot read properties of undefined (reading 'token')` | 上一步 401，响应只有 `error` 没有 `token`，脚本却按成功去取 → TypeError。根因还是登录路径错。 |
| `/api/ai/chat`、`/api/ai/price` 等返回 **503** | AI 服务没起。先起 `ai_service/server.py`；没起则 503（用例已接受为预期值）。 |
| `adminPassword` 留空时客服/管理端用例 | 按 401/403 被拒断言通过（顺带验权限基线）；填了真实管理员凭据才真正跑通。var-trial 无 `admin-initial-password.txt`。 |
| AI 多轮对话（带 history）曾断连 | `ai_service/server.py` 的 `_history()` 引用了已删除的 `rag.SOCIAL_REPLIES`，已于 2026-10-23 用 `getattr(rag, 'SOCIAL_REPLIES', {})` 兜底修掉，现 14 请求/50 断言全绿。 |
| `index.json` 不存在 | 在 `.gitignore`，CI/脚本都会先 `ingest.py` 现造（关键词检索，不要 Ollama）。 |
| `cmd.exe` 批处理乱码 | `.bat` 刻意写成英文 + 纯 ASCII，逻辑全在 `run_all.py`；中文 + `^` 续行会按字节截断命令行。 |
| 502 / 连接被拒 | 本地代理把 `127.0.0.1` 也代理走了；关掉「使用系统代理」或加 `NO_PROXY=127.0.0.1`。 |
| CSV 乱码 | `faq-cases.csv` 必须存 UTF-8，Excel「另存为 GBK」会全乱。 |
