# 0007 复用已有 AI 服务对接公开 FAQ

日期：2026-10-24。状态：本轮实现与合成验收中，禁止生产启用。

依据用户本轮明确指令与接手主文档，仅推进公开规则 FAQ。新副本基于交付 c92567d，旧试用工作区与 ai/borrow-open-source@6edfc13 均保留。后者已有独立 Python 检索/生成服务，因此采用服务端 HTTP ModelPort 适配；前端直接调用供应商、复制生成 SDK 到路由以及导入整套旧业务均不符合本轮边界。

`support/assistant` 拥有本用例。router/schema → AssistantService → ModelPort、KnowledgePort、IdentityPort；infrastructure 实现端口，bootstrap 唯一装配。IdentityPort 通过同一个 LegacyGateway 调原 `/api/me` 核实不透明 Bearer；只把可信 actor ID 留在应用层，身份超时返回 503，明确无效会话返回 401。Bearer、actor、订单和历史从不进入模型请求。

新增 POST `/api/v1/support/assistant/answer`，输入仅 question（1–800 字）与 UUID client_turn_id，拒绝隐藏角色/上下文/令牌字段。输出沿用 Envelope，包含 answer_text、mode、来源 document_id/title/version/content、handoff。来源只由已审核 FAQ 清单构造，不接受模型自报 citation。无匹配、敏感凭据和明确要求人工均不调用模型。文本始终纯文本呈现。

保留旧 AI 源码并记录来源 SHA，另加只提供 question/context 的认证内部 FAQ 入口，复用原 rag 生成/摘录函数，关闭商品工具与历史。本轮只使用 mock，不读取真实密钥或执行收费请求；显式配置 api 模式后才允许原供应商适配发起一次请求，仍不自动重试。知识清单与服务来源均在服务端配置，客户端不能选择目标 URL。

应用进程内以可信 actor + UUID + question 摘要合并并发和重放，异内容原键 409；成功和结果未知的失败都保留短期终态，同轮不自动重新计费。只保存短期公开问答内存，不持久化整段历史。进程重启或到期后无跨进程去重保证，不能宣称绝不重复计费。受限缓存满时明确拒绝，不驱逐进行中的调用；模型网络请求不在业务事务内。

明确的知识/配置调用前失败不占用轮次缓存与额度，恢复后可原键重试。模型只收到由服务端审核文档构造的公开主题与正文，原始自由问题仅在本站用于检索；这是凭据模式识别之外的额外边界。沿用30轮及两秒间隔保护，本片配额窗口明确定义为滚动24小时、仅单进程；有持久平台后再统一原按日规则，不假报跨进程限流。

唯一业务 writer 仍为旧服务。本切片不写账号、订单、账本、工单、信誉或客服认领；没有跨表原子写集合。人工入口仅将原问题作为当前账号内存草稿带到现有提交页，由用户检查后提交，再按原规则进入客服会话。账号切换和页面离开取消请求、丢弃迟到回答、清理内存；失败保留输入与原轮次。

验收分开记录：原交付基线复跑；身份/敏感输入/可信来源/并发与失败合同；真实回环 HTTP 合成旧会话、FAQ 服务、新 FastAPI；前端组件行为与四宽度浏览器。Worker、真实 D1/R2、微信真机、生产与收费模型均不在本次结论中。

回退：撤回新客服入口及组合根装配，关闭 AI 服务源站配置；旧客服工单和唯一交易 writer 保持原路径。无数据库迁移，无数据倒灌。
