# 0001 下单请求身份与 D1 参数预算

日期：2026-10-21。状态：本地实现，待真实 D1 验证和迁移。

## 问题

旧守卫按商品展开 13 个绑定参数，8 件时超过 D1 的 100 参数限制。旧幂等重放遗漏 `want_id`，且从可修改订单明细推断原始请求；提交结果未知时直接返回同键旧单。

## 决定

在旧 Worker 交易入口中，服务端预读商品与报价后，把快照编成一个 JSON 参数，在同一 D1 batch 的 SQL 守卫里通过 `json_each` 逐项重查。只允许内部构造 SQL，商品 ID、价格、交付方式、数据和已接受报价均在提交时再次比较。

新订单写入规范化请求的 SHA-256 摘要到 `orders.request_hash`。摘要包含排序后的商品 ID、交付、地点、预约和 `want_id`；所有读取旧结果的路径先比摘要。摘要只是幂等身份，不承担认证用途。旧订单摘要为 NULL 时使用原字段比较并包含 `want_id`，但订单已经修改时无法恢复其原始请求，这是历史数据限制。

## 影响和验证

已有表只增可空列，迁移需在部署新代码前核实并执行。合成旧库扩展和新库初始化测试已通过；20 件、报价竞态、重放异内容测试在 SQLite D1 模拟器中通过。真实 D1 的参数、事务、并发和 Python FFI 尚未验证，因此此代码尚不能作为生产发布依据。
