# 0006 本机身份与订单先通过新 FastAPI 兼容入口接入

日期：2026-10-24。状态：已实现并完成本机合成链路验证；不允许生产启用。

用户要求新 FastAPI 增加登录和订单，同时保留数据和原业务。真实数据库权威源仍未知，不能创建另一套可写订单/账号实现。

采用 `/api/v1/compat` 显式命名空间：HTTP schema 校验 → CompatService → LegacyGateway → 配置的本机旧服务。底层账号、授权、KDF、订单状态/账本事务仍由旧 writer 完成。bootstrap 是唯一装配点，前端通过 VITE_HUALI_COMPAT_API=1 选择已有操作；未迁移业务维持旧路径。

compat 的 Envelope.data 明确保留旧数字 ID、金额分和秒级时间，不假装规范化新 DTO。普通新领域仍遵守字符串 ID/整数分/UTC 毫秒。原 Bearer 继续有效，没有新 JWT 或已完成的 Cookie/CSRF 会话。

源站必须显式配置本机 HTTP 端口，生产拒绝启用；不跟随重定向、不用系统代理、不自动重放写入。健康检查 business_ready 仍为 false，compat_enabled 仅代表已装配。

本机测试覆盖同内容原键重放和一条双方订单链路，不代表完整幂等验收。本地旧 checkout 的异内容重放摘要校验与 Cloudflare 实现仍有差异，后续需按 0001 补齐并验证并发与历史兼容。完整迁移仍需提取单份业务用例和领域查询/原子端口，不能长期把 HTTP 兼容适配当成全部重构结果。

回退：关闭前端兼容开关并重新构建，业务回到原 `/api`；停用新 API 的兼容源站配置。因为没有第二个业务库，不做双库合并或数据倒灌。已完成的旧服务交易事实不因代码回退而撤销。
