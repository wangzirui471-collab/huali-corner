# 0003 旧媒体读取按资源关系授权

日期：2026-10-21。类型：BUG A04。状态：本地合成用例通过，待隔离 Worker 验证。

## 问题与决定

旧 Worker 通过 `LIKE '%/media/<id>%'` 判断商品或订单是否引用图片，会把历史订单图片变成匿名资源，并允许所有员工直接读取任意私密凭证。

保持现有 `/media/<upload_id>` 和上传记录表，使用精确的 JSON 照片编号、照片 URL、订单商品编号和快照 URL 判断关系。只允许在售且卖家 active 的公开商品图匿名读取；历史图允许 active 上传者及交易参与方；私密凭证允许 active 上传者或有具体案件权限的处理人。其他卖家引用图片不能改变其权限。

员工须传 `?ticket_id=<id>`，且为关联工单处理人，或已认领关联且开放的客服会话并为成员；员工不能是该工单提交人或涉事商品/交易参与者。角色本身不再构成凭证读取权限。现有前端未提供凭证查看入口；后续入口须携带案件上下文。

所有动态图片成功响应使用 `private, no-store`，避免下架、停用或解除认领后继续共享缓存。拒绝授权时不读取 R2。

## 兼容及限制

本次不迁移数据；T03 的结构化媒体关系可以替换这一旧 JSON 适配器。订单快照的 `photo` 保持精确读取，即使商品记录已不存在，合法参与方仍能读取历史照片。私密凭证若已丢失商品关联则保守拒绝员工，不能从任意订单正文推断关联。

新响应头不能撤回已经发出的旧 `public, max-age=3600` 缓存。实际发布前须核对旧缓存策略，在发布步骤执行明确的缓存失效或等待其过期并验证；本轮没有执行远程缓存操作。

`tests/test_cloudflare_media.py` 共 10 个用例覆盖匿名/第三人/无关员工拒绝、交易双方、凭证、精确引用、卖家归属、账号停用、认领释放、利益冲突、缺失商品历史快照、授权拒绝不读 R2。`tests/test_cloudflare_catalog.py` 的凭证用例改为新合同，不再保留旧员工全局旁路。两文件共 36 项通过。
