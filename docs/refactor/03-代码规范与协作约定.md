# 03 代码规范与协作约定

版本 1.0｜2026-10-21。适用于重构中的新增文件和实际修改代码；旧文件逐模块迁移。工具配置在 T02 落地后成为自动检查，本文本身不代表配置已存在。

当前前端选型由用户更新为 **JavaScript + Vue 3 + Element Plus**，见 [0004](./decisions/0004-javascript-element-plus.md)。下文原 TypeScript 示例用于说明协议和组件边界，实际实现使用 `.js`、中文 JSDoc、运行时 props 和 checkJs；不编写 TypeScript 业务源码。Element Plus 通过 shared/ui 适配品牌与交互。

## 1. 规则等级与设计责任

“必须/禁止”用于正确性、数据、权限、边界和确定的风格合同；“建议”允许说明理由后调整。现存代码与规则不一致时登记技术债，不能为了消除警告全仓重排或隐去测试失败。

每个功能只有一个业务所有者、一个写入权威路径、一个前端入口模块。新增功能先确定所属领域，再编码。共享目录只容纳确实被至少两个领域使用且语义一致的基础能力；不建立 `common_service`、`utils2`、万能 BaseService 或继承树收纳所有内容。

跨模块调用以明确的 service/port/DTO 为边界，依赖通过构造函数或组合根注入。禁止新增 Market mixin、全局可变单例、从业务层访问 `self.env`、从规则层 import HTTP/Worker/DB。事务所有者由应用用例决定，仓储不悄悄提交。

架构变更记录到 `docs/refactor/decisions/`（实施时创建），写问题、决定、理由、影响和如何验证即可；常规字段/组件不必写长篇 ADR。改变数据库、认证协议、API 单位、跨模块依赖或引入服务时，必须有决策记录。

## 2. 命名、格式与可读性

| 项目 | 统一规则 |
| --- | --- |
| Python | 4 空格；Ruff format 默认双引号；目标行宽 88；函数/文件/变量 snake_case；类 PascalCase |
| TS/Vue/CSS | 2 空格；Prettier 单引号、分号开启、行宽 100；Vue SFC 由同一 formatter 处理 |
| Vue 文件 | 业务组件 PascalCase：`ProductCard.vue`、`OrderTimeline.vue`；页面 `ProductDetailPage.vue` |
| TS 文件 | kebab-case：`catalog-api.ts`、`product-mapper.ts`；composable `use-product-feed.ts` |
| 函数与变量 | TS camelCase；composable `useXxx`；Pinia `useXxxStore`，store ID 在应用内唯一 |
| JSON / DB | 新增字段 snake_case；旧字段通过兼容 DTO 保持；金额 `_cents`，时间单位写进契约 |
| 常量 | Python/TS 业务常量 UPPER_SNAKE_CASE；带单位：`PAYMENT_TIMEOUT_SECONDS` |
| CSS | 类名 kebab-case，必要时 `product-card__price`；状态优先 aria/data 属性或少量 is-* |
| 编码 | UTF-8、LF、文件末尾换行；PowerShell 命令对中文/空格路径加引号 |

标识符使用清楚的英文业务词，中文用于产品文案和说明业务理由的注释。统一实体名 user/product/order/ticket/want/room/message/upload；不要同义混用 goods/item/product。局部循环索引或 SQL 别名允许短名；业务参数禁止用 `u/d/r/a` 代替 actor/command/order。

一行只表达一个业务动作；禁止用分号把验证、更新和返回压在一行。函数超过约 60 行或文件超过约 350 行时做职责检查，这些是复审信号，不是机械拆文件指标。拆分必须减少知识耦合，不为行数制造转发空壳。

注释解释约束和原因，例如“同一订单的部分退款只能结案一次”；避免“给 status 赋值”这类复述。协议、金额公式、并发守卫和补偿需要注释；普通显然代码不逐行翻译。历史平台经验标注日期/版本，不能写“永远不允许改”阻止重新验证。

实施补充（用户于 2026-10-21 明确要求）：所有新增和重构涉及的函数、方法、测试与任务脚本都加中文注释，说明用途及必要的参数、返回结果和限制。Python 使用 docstring，TypeScript 使用 JSDoc；复杂步骤解释业务原因，使初学者能理解。旧模块随迁移补齐。

## 3. Python 后端风格

新业务模块使用明确类型的输入、输出和依赖。HTTP schema 负责输入边界；纯规则接受 dataclass/明确模型并返回决定；不要在内部不断传无类型大 dict。对 FFI 与旧数据可使用受限的适配类型，统一归一化后交给业务，不在每个服务到处调用 `getattr`。

```python
@dataclass(frozen=True)
class OrderTotals:
    subtotal_cents: int
    delivery_fee_cents: int
    total_cents: int


def calculate_totals(items: Sequence[CheckoutItem], delivery: str) -> OrderTotals:
    subtotal_cents = sum(item.price_cents for item in items)
    delivery_fee_cents = (
        max(item.delivery_fee_cents for item in items) if delivery == "delivery" else 0
    )
    return OrderTotals(
        subtotal_cents=subtotal_cents,
        delivery_fee_cents=delivery_fee_cents,
        total_cents=subtotal_cents + delivery_fee_cents,
    )
```

示例假定输入已经非空且通过业务验证，`CheckoutItem`/imports 在真实模块定义；不把片段直接作为完整可运行文件。金额边界拒绝 bool、浮点和非法数值；运算用整数分；舍入规则按具体业务说明，不能通过 `int(float(x)*100)` 悄悄截断。

异步 I/O 显式 await。纯规则不为形式统一改成 async。路由 handler 调用一个用例，不能在 handler 中塞入多表交易 SQL。读取 SQL 可以在领域查询适配器中直接写，不强制每张表都有泛型仓储。

错误使用有语义的代码和上下文：`VERSION_CONFLICT`、`IDEMPOTENCY_MISMATCH`、`FORBIDDEN`。边界统一转 HTTP；内部函数不返回 `{ok:false}` 让调用者误当成功。不捕获 Exception 后静默返回默认值；只在协议边界、补偿和提交结果未知时进行明确兜底，并保留脱敏诊断。

时钟、随机 ID 和 token 生成通过少量明确接口注入。测试固定时间，无需为时间测试真实 sleep。权限测试使用明确的 actor/资源 fixture；不通过“管理员通配”跳过业务归属和利益冲突。

目标运行时先按 Workers 官方 FastAPI 示例验证 Python 3.13+，在 T01 固定 SDK 与兼容日期；旧本地代码若仍承诺旧 Python 版本，不给其顺带引入不兼容类型语法。最终支持版本写进 pyproject、开发说明与 CI，不同时宣称未经测试的 3.8/3.12/Worker 均可用。

## 4. D1、SQL 与数据迁移规范

SQL 值使用参数绑定。可排序字段、操作类型、表名只能来自内部白名单；客户端输入不得用于字符串拼接 SQL 标识符。批量查询使用有界集合，生成器在提交前检查单语句参数数/字节数。

数据库约束承担最后防线，业务服务提供可理解的前置错误。每个高风险写入必须列出不变量和同 batch 的数据集合。禁止以下写法：

```text
UPDATE 若命中0行也继续；提交后才 expect 并以为已回滚
多个 await run 组成“假事务”
INSERT OR IGNORE 吞掉关键账本金额不一致
先写退款后另写通知/工单，失败时任一半成功
仅凭页面禁用按钮避免重复提交
```

迁移文件采用编号和说明名，如 `0003_add_order_reservation_version.sql`。已部署迁移不可原地改写；新错误通过新迁移修复。迁移必须有旧库升级、新库初始化、重跑/中断恢复、约束和对账样例。兼容期先加可空列/新表，回填校验后再加强约束；不能直接用新 NOT NULL 阻断旧写入。

真实数据、凭据、数据库文件、备份、环境文件和包含敏感信息的日志都不提交。测试 fixture 必须合成；脱敏数据仍需确认不能复原个人身份。

## 5. Vue 与 TypeScript 风格

使用 Composition API、`<script setup lang="ts">`、类型化 props/emits。组件结构顺序统一为 script、template、style。用 computed 表达派生状态，watch 只处理真正副作用；禁止多个 watcher 互相改同一状态形成隐式流程。[Vue TypeScript 文档](https://vuejs.org/guide/typescript/overview.html)

页面组织查询和交互，组件呈现内容，composable 管理可复用生命周期与操作。组件不直接 fetch 或访问 localStorage；API 模块只负责协议，mapper 只转换 DTO；需要持久化时使用按账号命名的 storage adapter。

```vue
<script setup lang="ts">
import { RouterLink } from 'vue-router';
import AppButton from '@/shared/ui/AppButton.vue';
import type { ProductSummary } from '../types';

defineProps<{ product: ProductSummary; isSaving: boolean }>();
const emit = defineEmits<{ favorite: [productId: string] }>();
</script>

<template>
  <article class="product-card">
    <RouterLink :to="`/products/${product.id}`">{{ product.title }}</RouterLink>
    <AppButton :disabled="isSaving" @click="emit('favorite', product.id)">
      {{ product.isFavorite ? '取消收藏' : '收藏' }}
    </AppButton>
  </article>
</template>
```

示例组件/类型是目标文件，T02/T03 中实施，统一使用显式 import。循环使用稳定实体 key，禁止 index key 承载可变列表/输入。模板禁止不可信 `v-html`；富文本另做经过审查的渲染与白名单。

TypeScript 开启 strict，组件、API 与 store 禁止泛用 any；外部未知值使用 unknown 后校验。必要的类型抑制须范围小、说明来源和移除条件；不能全局关闭 noImplicitAny。状态值使用字面量联合和集中映射，禁止业务字符串散落各页。

Pinia 按领域划分，采用 setup store，并从 store 使用 storeToRefs 保持响应性。禁止把整个应用对象存入一个 store，禁止多个 store 持有可独立修改的同一订单事实。[Pinia 文档](https://pinia.vuejs.org/core-concepts/)

资源清理在统一 composable 生命周期完成：AbortController、timer、observer、监听器、Blob URL 都有销毁路径。账号切换先清除私密内存与旧请求，再获取新身份；同一页面的旧响应也不能覆盖新搜索结果。写操作区分提交中、已成功、明确失败和结果未知。

表单只在服务端明确成功后清除。按钮禁用防误点，幂等防重复业务；两者都要做。表单错误紧邻字段；业务错误提供操作出口，不只弹瞬间 toast。

## 6. CSS、组件和素材规则

遵守 04 的设计令牌。应用全局只定义 reset、tokens、字体和基础布局；基础组件统一按钮/表单/弹窗/反馈；页面使用 scoped 样式。禁止以全局 `.btn` 覆盖修复某一页，也禁止连续在 CSS 尾部追加同选择器。

新增颜色、间距、圆角优先已有 token；确需新增先说明语义，不为每个页面创造主题。动态数值可使用 CSS custom property，普通内联样式仅在确有运行时计算时使用。新组件禁止使用 `!important` 解决职责冲突；第三方样式适配的必要例外写在专用 adapter 并说明。

不混用两套 UI 框架。用户端先用本项目基础组件；复杂后台组件若确需库支持，独立决定并包在 adapter 内，不能让库默认主题覆盖整个品牌。图标保持同一 SVG 系统和线宽；Logo 使用已有素材，不能从文字/emoji 重新拼一个近似标志。

商品图片保留原图浏览与正确比例，列表裁切只影响展示。给尺寸/aspect-ratio 避免布局跳动，非首屏懒加载。演示素材与真实上传明确分开，授权来源保留；错误头像/图片要有稳定 fallback。

## 7. 工具、脚本与自动检查目标

T02 建立并锁定工具版本：后端 Ruff check/format + mypy（新纯规则/服务严格、FFI adapter 局部适配）；前端 ESLint + eslint-plugin-vue + TypeScript + vue-tsc + Prettier。保留既有 unittest，前端新单元/组件用 Vitest 与 Vue Test Utils，关键浏览器流程用 Playwright。不要为实现同一检查再引入第二套工具。

拟建统一脚本合同：`npm run lint`、`npm run typecheck`、`npm run test:unit`、`npm run build`；后端固定环境内 `python -m unittest ...`、`ruff check`、`ruff format --check`、`mypy`。这些命令在对应配置落地前属于计划，不在当前仓库直接运行并声称缺少脚本是产品故障。

CI 目标按增量启用：格式/类型 → 模块边界 → 规则/API 合同 → 本地 Worker → 浏览器 → 隔离平台验收。交易、权限、迁移等关键测试必须通过；不为了迁移“先让 CI 绿”而删除或 weaken 断言。覆盖率作为缺口线索，不以数字替代抢单/退款失败路径。

依赖锁文件入库，构建用锁定安装。只读核对可随时进行；安装、远程测试和发布按实际环境权限执行，不能默认使用现有 remote:true 配置。配置模板含示例占位符，生产变量校验失败应明确停止，不自动回退到演示库。

## 8. 新增功能的固定实施模板

每个需求提交前填完以下内容，可保持一页：

```text
功能/任务编号：
变更类型：REF 结构迁移 / BUG 缺陷 / RULE 规则变更 / FEATURE 新增
用户目标与入口：
所属后端/前端模块：
API 与存量客户端兼容：
权限：角色 + 归属 + 状态 + 利益冲突
写入不变量、原子集合、幂等键与失败补偿：
数据迁移与回滚边界：
复用布局/组件/token，新组件存在的理由：
加载/内容/空态/错误/无权/提交状态及手机行为：
自动测试、截图和人工检查证据：
尚未验证的环境/能力：
```

例如“新增商品举报”应属于 catalog/moderation 与 support 工作流，复用 AppDialog/FormField/StatusBadge；权限、重复举报、关联工单、内部审核细节保护一起设计。不能只加一个红按钮，就把后端、工单、通知和各种空错误状态留给下一人猜。

## 9. 提交、审查与完成标准

一个提交对应一个可解释的任务或业务切片，可包含该切片的 API、页面、测试和迁移。提交格式 `refactor(trade): ...`、`fix(media): ...`、`feat(catalog): ...`、`docs(refactor): ...`。不要同时重排所有文件、替换依赖、改规则和改界面，导致回归无法定位。

审查说明写结果、理由、兼容/数据影响、实际验证与剩余限制。新增/修改文件列准确路径；测试列命令、环境、数量和失败，浏览器截图注明尺寸/身份/状态。日志中的真实凭据、账号和 private URL 脱敏。

完成必须同时满足：功能合同与失败路径、模块边界、类型和格式、03 的代码约定、04 的视觉及交互、相应迁移与恢复检查。不能用“按钮能点”代表功能完成，也不能用“目录清楚”代表业务重构已完成。
