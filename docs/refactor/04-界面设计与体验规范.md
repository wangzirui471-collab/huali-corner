# 04 界面设计与体验规范

版本 1.0｜2026-10-21。目标是让用户觉得清楚、轻快、有校园生活感，让接手模型能延续同一套设计。美观通过可复用的令牌、组件和真实页面验收维持，不能只交一张理想状态首页图。

实施更新：用户已选择 Element Plus 作为 Vue 3 控件库，见 [0004](./decisions/0004-javascript-element-plus.md)。共用组件通过适配层统一品牌、错误文案、44px 触控目标和键盘行为；保留以下布局及交互标准。

## 1. 视觉方向与现有基线

保留 `b2b6266` 的识别度：紫色 ZJ 标识、暖黄操作色、白色内容卡、低饱和专题底色、商品实拍大图和紧凑信息层次。Logo 直接引用 `assets/logo-mark*`、`logo-zj.svg`、`logo-lockup.svg`，源素材中的紫色 `#7F68AF`、黄色 `#F9C708` 保留，不随页面临时改色。

用户端像一处整理清楚的校园二手集市；后台像清楚可靠的工作台。两者共用品牌、字体、控件、状态语义，后台可采用更紧凑的信息密度。避免大面积紫色渐变、玻璃拟态、多重阴影、满屏装饰和模仿电商促销的大红价格。

迁移先建立当前界面的截图和交互基线，再逐页用 Vue 替换。统一令牌、增强文字对比度和改善可访问性属于明确的 UI/BUG 任务，不能把重新排版悄悄混进纯技术迁移。

## 2. 设计令牌

以下为目标令牌，T02 在组件样板页验证后固定。Logo 的素材颜色与 UI 文本颜色分别管理；Logo 紫不直接承担所有正文/链接颜色。

| token | 建议值 | 用法 |
| --- | --- | --- |
| color-brand-mark | `#7F68AF` | 品牌识别及少量装饰，Logo 仍引用源文件 |
| color-action | `#F5CA54` | 主要操作底色，沿用现首页暖黄 |
| color-action-hover | `#E9BC42` | 主操作 hover |
| color-action-ink | `#3E341B` | 黄色按钮文字；禁止黄底白字 |
| color-link / color-focus | `#68509C` | 链接、焦点、轻量品牌强调 |
| color-canvas | `#F6F7F9` | 页面背景 |
| color-surface / color-surface-subtle | `#FFFFFF` / `#F9FAFB` | 卡片、表单、分组背景 |
| color-text | `#20232A` | 主要文字 |
| color-text-secondary | `#4B5260` | 辅助说明 |
| color-text-muted | `#626872` | 次要信息，仍要求可读 |
| color-border / color-control-border | `#E5E7EB` / `#8C939F` | 前者为装饰分隔，后者为输入控件边界 |
| color-price | `#8A5B1A` | 温和金棕价格，避免浅棕细字看不清 |
| color-success / color-danger | `#23764C` / `#B3372B` | 成功/风险，文字与状态标签共同表达 |
| color-warning-ink / color-warning-bg | `#89620F` / `#FFF5D6` | 待处理与提醒 |

普通文字对比度至少 4.5:1，大字至少 3:1；焦点、图标和控件边界还须检查其实际背景和可见性。颜色表是设计起点，不能用“颜色选过了”代替合成后的页面检查。Logo 和纯装饰与业务文字的判断不同。[W3C 对比度说明，核实于 2026-10-21](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

本轮按 sRGB 相对亮度计算校验了七组纯色文字/底色：黄色主按钮文字 7.86:1、次要文字 5.61:1、链接 6.53:1、价格 5.85:1、危险 6.00:1、成功 5.57:1、警告底色上的文字 5.05:1。这里只证明这些组合的数值，不涵盖透明度、渐变、实际字号或渲染界面的完整可访问性。

| 系统 | 统一值/规则 |
| --- | --- |
| 字体 | system-ui、PingFang SC、Microsoft YaHei 等本机中文无衬线；暂不下载大体积外部字体 |
| 字号 | 页面标题 28–32；区域标题 20–24；主正文 14–16；次要信息 12–13；表单输入手机至少 16 |
| 行高 | 正文 1.6，标题约 1.3，数字控件按组件测量；不缩小正文挤布局 |
| 字重 | 400/500/600/700；价格可 700；不靠每段加粗制造层次 |
| 间距 | 4、8、12、16、20、24、32、48；组件内紧、同组适中、组间宽 |
| 圆角 | 控件 8，卡片 12，专题/弹窗 16；pill 仅用于标签/切换，不给所有容器胶囊化 |
| 阴影 | 卡片最多轻微一级，浮层二级；禁用状态不靠加阴影强调 |
| 动效 | 120–180ms，主要改变透明度/小幅位移；避免 scale 放大整张商品图和布局跳动 |
| 层级 | header 10、手机导航 20、浮层 30、toast 40，集中管理 |
| 触控 | 核心触控目标至少 44×44 CSS px；圆点可小，实际点击区不能只有 4px |

颜色/间距/圆角放在 `shared/design-tokens` 与全局 CSS custom properties；组件只引用语义 token。确需新增先说明用法，不能给每个 feature 添自己的 primary/danger。

## 3. 布局与响应式

桌面内容最大宽度沿用 1240px 左右，左右留白至少 24px；手机留白 12–16px。主内容、标题、筛选、列表和底部操作使用同一条对齐线。大屏不无限拉长表单和聊天气泡。

| 宽度 | 用户端目标 |
| --- | --- |
| 320/360/390/430 | 商品双列，文字保留两行；五槽底栏，发布居中，“我的”从右上头像进入 |
| 768 | 搜索、双专题和列表自然展开；不出现桌面/手机两套导航同时抢占空间 |
| 1024 | 商品可 3–4 列；详情可双区；工作台侧栏按空间折叠 |
| 1280/1440 | 商品 4 列为默认，最大宽度容器；工作台列表与详情可并排 |

断点由容器内容决定，不能只按设备名。不要为了保持列数把商品卡字体缩到 10px。`min-width:0`、长文本换行、表格局部滚动、safe-area 要在组件层处理。页面级横向溢出为阻塞项。

页头包含品牌、学校/试点上下文、搜索、消息、清单与账号。模拟交易说明清楚但不过度抢占首屏；不使用让人误以为已实名或已接支付的标识。所有固定底栏都给主内容和表单操作留出遮挡空间。

## 4. 页面构成与线框

### 4.1 首页和商品流

保持最新结构：头部搜索/导航 → 商品频道 → 九个快捷入口 → 两个紧凑专题窗口 → 商品推荐。首屏让商品和入口可见，专题不能膨胀成占满一屏的宣传海报。

```text
桌面
┌ 品牌 / 校区 ─────── 搜索 ─────── 消息 / 清单 / 账号 ┐
│ 逛逛  社区  论坛  我的                    发布闲置 │
│ 商品频道 + 快捷入口                              │
│ [书籍/宿舍/运动专题]    [校园/免费送/发布专题]       │
│ 猜你喜欢                       最新 / 价格 / 筛选 │
│ [商品]       [商品]       [商品]       [商品]       │
└──────────────────────────────────────────────────┘
手机
┌ ZJ / 华立转角                 消息  清单  头像 ┐
│ 搜索                                         │
│ 横向频道 / 紧凑快捷入口                        │
│ 两个专题窗口：按可读宽度并排或上下排列           │
│ 商品推荐 + 筛选                               │
│ [商品]                 [商品]                 │
├ 逛逛 ─ 社区 ─ 居中发布 ─ 论坛 ─ 消息 ─────────┤
└──────────────────────────────────────────────┘
```

两个窗口各保留三张及六个真实目标入口；小屏是否堆叠通过 320/390 预览选择，不能删掉其中一个，也不能让插图遮住文案。专题默认文字占主体，插图低对比、次要地位。

商品流保留 24 件分页、追加去重、失败后原列表仍在、手动加载兜底、返回位置、收藏就地反馈、回到顶部。免费送显示“物品免费，交付费用看详情”；收藏不暗示预留。公共卡片不显示平台下架；详情、自主发布管理和工作台分别提供合法管理入口。

### 4.2 商品卡片与详情

卡片：方形图片 → 两行标题 → 金棕价格和必要状态 → 交付地点/方式 → 卖家与收藏。图片铺满裁切，留稳定比例；缺图显示有意义的占位，不能换上随机商品图。价格靠前但不压住标题，送货费单列。标题超长使用两行截断，完整名称在详情可读。

整张卡片不能是包含多个按钮的嵌套按钮。图片和标题为详情链接，收藏为独立按钮；焦点/hover/已收藏/处理中/失败状态都可辨认。卡片高度和卖家行对齐，失败重试不改变网格尺寸。

详情桌面图片区与交易摘要双区，手机先图后信息。明确分类属性、商品状态、三视图、描述、卖家、交付方式、模拟金额和规则；主要操作固定在可见位置但不遮正文。reserved/sold/removed 展示原因允许的范围，禁止仍给出可成功下单的外观。

### 4.3 发布与表单

按“基本信息 → 分类属性 → 实拍图片 → 价格与交付”分组；每组标题和说明清楚，不强制拆成多步向导。分类切换时保留可共享输入，清除无效属性有明确说明。

三视图用带文字的正面/侧面/顶部槽位，展示上传中、成功、重复、失败、重选。不要只靠绿色边框表示有效。上传前解释格式/尺寸；服务端不通过时错误靠近对应图片。离开时草稿保存状态明确，不保证图片跨设备恢复。

保存/发布中保持按钮宽度、显示文字与 loading；失败保留所有输入；成功后给详情或“继续发布”的真实出口。字段校验统一 FormField，不通过 placeholder 替代 label。

### 4.4 订单与售后

订单卡片显示状态、快照商品、金额明细、交付预约、下一步主体和截止时间。倒计时只用于辅助，绝对时刻和状态由服务端决定。卖家确认交付、买家确认交接、确认收货的文案和按钮分清，不能都写“完成”。

关键操作弹窗说明具体后果：模拟付款金额、取消释放条件、退款额度及商品保持下架。部分退款输入整数分/金额转换统一；显示可退上限与账务结果，不使用模糊的“处理中”掩盖结果未知。

时间线只描述实际已发生事件，未发生步骤中性显示；售后处理中展示暂停自动收货。内部备注必须有独立样式与清楚的“仅平台可见”，但是否可读仍由服务器判断。

### 4.5 社区、论坛与聊天

新版社区与论坛继续分入口。求购在论坛指定入口和上下文展示，避免两个页面各维护一份发布/回复流程。帖子区分作者、时间、内容和操作，说明引用/折叠来源；长内容有明确展开，不能靠压缩字号。

聊天桌面为会话列表 + 当前会话，手机打开会话后聚焦消息内容。自己的消息与他人消息通过位置、底色和标识共同区分；头像/昵称能识别，气泡最大宽度约 70%–80%，长链接能换行。

发送中、失败重发、已发送、撤回、被移除分别有状态。失败消息保留原位置；重试不生成第二条气泡。拉黑、非好友、禁言和已关闭客服会话给出对应原因与可执行出口，输入区不要只是灰掉无解释。键盘弹出时输入区、底部导航和 safe-area 不互相遮挡。

### 4.6 客服/管理工作台

共用 WorkspaceLayout：侧栏任务导航、页面标题、少量真实指标、筛选区、列表和详情。优先帮助处理事情，不用大量无意义统计卡挤占空间。用户端暖黄只用于主要操作，危险处置使用 danger 语义。

工单、内容审核、人员、审计和资金页使用共用 DataTable/FilterBar/DetailPanel。表格有表头、清楚的选中/空态/加载/排序；金额和时刻对齐，长 ID 可复制。权限决定可见操作，同时显示处置理由和历史。

小屏改为摘要行/卡片 + 详情抽屉，或在表格容器内横向滚动；整页不横向滚。关键金额、状态、对象、下一步不能因响应式隐藏后完全不可访问。

## 5. 共用组件合同

| 组件 | 必须统一的行为 |
| --- | --- |
| AppButton / IconButton | primary/secondary/quiet/danger；size；loading/disabled/focus；图标按钮有名称 |
| FormField / AppInput / Select / Textarea | label、help、error、required、disabled；错误与输入通过 aria 关联 |
| AppDialog / ConfirmDialog / Drawer | 标题、说明、焦点进入/限制/返回；Esc；背景不可交互；异步失败保留内容 |
| StatusBadge | 状态机器值映射显示；文字/图标和颜色共同表达，禁止每页自造色 |
| AsyncState / EmptyState / InlineError | 统一六类状态布局；重试与真实下一步；可保留旧内容 |
| ProductCard / UserAvatar / MoneyText | 比例、缺图、脱敏、整数分格式、免费与送货信息一致 |
| FilterBar / Pagination / LoadMore | URL 可恢复、清除条件、追加失败重试、手动加载 |
| OrderTimeline / TicketThread | 时间与参与者、事件含义、内部/公开信息区分 |
| Toast / InlineNotice | 短暂反馈与持久错误分别使用；不只依靠颜色，不让瞬时 toast 承载关键失败 |

实施 T02 建一个**只在开发/隔离预览环境启用的组件样板页**，展示所有变体、长文本、失效图片与状态。生产不暴露测试账号或调试数据。新功能优先复用；确有新交互时先补样板，再用于页面。

## 6. 每页必须覆盖的状态

| 状态 | 用户应该看到什么 |
| --- | --- |
| 首次加载 | 与实际布局接近的轻量 skeleton；明确 aria-busy，不整页无说明白屏 |
| 正常内容 | 层级、主要操作和状态清楚，真实长文本也能承载 |
| 空结果/首次使用 | 分清“没有商品”与“筛选无结果”，分别提供发布/清除筛选等出口 |
| 失败/离线 | 保留已有内容和输入，显示重试；未知提交结果提供核对，不能诱导重复付款 |
| 未登录/无权/资源消失 | 与系统故障区别表达，给登录、返回列表或联系平台出口 |
| 提交/不可用 | 可见进行中、防重复、失败后恢复；禁用有原因，最终结果不靠猜 |

验收覆盖访客、本人、普通他人、客服、管理员、开发者及资源不同状态，不要求所有身份都有菜单，但必须验证无权入口和接口表现一致。

## 7. 可访问性与轮播变更登记

键盘可完成搜索、筛选、收藏、发布、订单操作及对话框；焦点可见，弹窗关闭回到触发点。语义化 heading/nav/main/button/link，错误用文本，异步重要反馈使用合适的 live region。放大到 200% 仍可读、可操作。图片含信息时给 alt，装饰图空 alt；颜色不是唯一状态提示。

现版双轮播经文档明确记录为持续播放、没有暂停，悬停/聚焦继续轮换，减少动效仅关闭过渡。**REF 迁移先如实保留和测试，不将历史行为写成已经满足可访问性。** 建议单列 UX-01：加入可暂停方式、悬停/聚焦暂停、页面隐藏暂停、prefers-reduced-motion 下关闭自动轮换；保留双窗口、六个目标、紧凑尺寸。进入实现时明确记录这项体验变更并更新现有 `home_promos` 测试，不能偷偷删断言换通过。[W3C 轮播指南，核实于 2026-10-21](https://www.w3.org/WAI/tutorials/carousels/)

其他独立改进：UX-02 收敛浅灰小字与价格对比；UX-03 统一移动端弹层/键盘/固定操作栏；UX-04 工作台窄屏摘要与详情。每项可独立提交，避免和核心账务迁移揉成一次大改。

## 8. 美观与体验的完成标准

每个页面至少提交 320、390、768、1440 四种宽度的可重复截图；后台再补 1280。首页、商品详情、含图发布、订单/退款、聊天、工单列表/详情为首批关键页面。截图来自隔离测试数据，避免真实个人信息。

验收清单：

- 同一组内容沿同一对齐线，间距与圆角来自令牌；按钮/输入/标签的高度和基线一致。
- 没有横向溢出、遮挡、断裂图片、突然跳高、焦点丢失；长标题、长昵称、0 元和大金额都正常。
- 正文及价格清楚可读，没有用浅灰细小文字承载必要信息；状态不只靠颜色。
- 同功能在用户端和工作台用相同术语、金额/时间/状态规则；主要动作一眼能找到。
- 手机触控目标、safe-area、键盘与底部导航通过实际浏览器检查；不能只把桌面截图缩小。
- 加载/空/错误/无权/提交态有对应截图或交互记录，失败保留输入、原列表和登录。
- 当前品牌、双专题、五槽导航、右上个人入口及关键交互通过迁移对比；明确批准的 UX 变更另列。

建立 Playwright 视觉回归时固定字体环境、视口、测试数据、时钟并暂停测试动画。像素差异作为审查证据，不自动批准新的基准；产品图片动态区域可受控屏蔽，但不能屏蔽按钮/金额/状态。最终由真实页面的视觉复核判断是否协调，自动检查负责守住可量化底线。

本轮交付的是设计和验收标准，没有生成或验收新的 Vue 界面。不得把这份规范写成“新站已完成美化”。
