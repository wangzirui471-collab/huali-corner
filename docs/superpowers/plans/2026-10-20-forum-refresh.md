# 校园论坛界面改版 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将现有求购、交换人生、代拿快递论坛改为白底、清晰分区、适合阅读的首页、列表和独立帖子详情页。

**Architecture:** 保持原生 ES Module、hash 路由和现有交易/好友规则。新增独立论坛组件、页面与事件模块以及作用域样式。现有 posts/comments 读取接口补充筛选、单帖与 20 条回复游标参数，本地与云端共用查询契约，不迁移数据。

**Tech Stack:** HTML/CSS、原生 JavaScript、Python/SQLite/D1、Node tests、独立 Chrome 浏览器测试。

**Spec:** 用户 2026-10-20 消息及“你直接看着改”的实施授权。

## Global Constraints

- 大面积白底；卡片简洁柔和；动效仅简短过渡；同时适配 PC 与移动端。
- 禁止彩色标签堆砌、表情包铺屏、悬浮广告、闪烁装饰和暗黑花哨风格。
- 保留三个真实板块及求购匹配、好友申请、举报与审核权限。
- 不改用户已完成的登录缓存，不覆盖真实数据，不伪造浏览量、认证、置顶或帖子数量。
- 现有接口没有浏览量和帖子置顶字段；组件兼容未来真实字段，当前只展示已具备的真实回复/匹配数。

## Review Focus

- 旧帖只有正文：首行生成阅读标题，不丢失正文，不把用户输入当 HTML。
- 回复超过一页、父回复不在当前页：游标不重复、顺序稳定，保留回复对象。
- 部分板块接口失败：已成功加载的板块仍可浏览，不把错误冒充空数据。
- 页面切换期间的慢响应：不覆盖新路由，不丢失其他页面的状态。
- 手机端长标题、长链接和空板块：无横向溢出，导航与操作可触达。

## Tasks

- [ ] 1. 先增加并运行读取契约与组件回归测试；实现查询筛选、排序和回复分页，保持旧接口默认行为。
- [ ] 2. 实现论坛首页/板块列表、搜索、最新/热门、列表/卡片切换，增加独立详情和内联回复编辑器。
- [ ] 3. 实现统一白底样式、阅读宽度、轻回复卡片，收敛个人中心和消息页视觉；保持现有功能入口。
- [ ] 4. 运行相关本地/云端契约和前端测试；用临时数据库在 PC/手机真实 Chrome 中检查发帖、读帖、分页、回复及布局。
- [ ] 5. 保存验证结果和页面截图，报告本次改版与尚未具备的数据字段。
