# 转角 Cloudflare 可登录试用版迁移设计

日期：2026-10-17。检查基线：`master @ 05e6642`。状态：**待用户审阅；未实施业务迁移，未创建线上资源，未发布公网网站**。

## 目标与范围

用户希望先试用免费托管，暂不购买 Linux 云服务器，让计算机学院同学通过统一网址注册、发布实拍商品、聊天、下单和提交售后。继续使用 Python 维护业务数据与规则，保留前后端模块分层；不接入真实短信、身份核验、微信收款、退款或打款。

首个可登录版本必须保留已承诺的账号隔离、三视图、商品详情、收藏、出价、同卖家合并订单、模拟账本、交接与自动收货、售后举报、客服和管理员权限。新合并的改名与头像功能也属于兼容范围。不能将静态演示的虚构数据接口当作可登录后端，也不能为了部署成功删除交易校验。

没有收到真实本机数据，不默认搬运或合并账号、订单。线上先使用新的独立试用数据；后续迁移真实数据需单独核对源库和图片，不覆盖已产生新数据的线上库。

## 已确认的现状

- 本地后端用 `ThreadingHTTPServer` 接收请求；业务通过 SQLite / MySQL 同步连接访问数据。
- 商品与头像经 Pillow 处理后写入数据目录；备份生成本地 SQLite 与图片 ZIP。
- 订单超时通过后台线程每 30 秒轮询。聊天通过浏览器定期请求接口。
- 登录密码使用独立盐的 PBKDF2-HMAC-SHA256（600000 轮），令牌和恢复码保存摘要。
- 没有 Cloudflare Worker 入口、D1 / R2 绑定或可登录托管版构建配置。把现有目录上传到 Pages 只能托管网页，不能启动这套后端。

## 选择的架构与替代方案

目标采用 **Workers 静态资源 + Python Worker + D1 + R2 + Cron Triggers**，网页与 `/api` 同源，暂不拆成多个域名。选择单个 Worker 承载网页和接口是为了保持当前相对路径，减少跨域配置与额外组件。

另一条可行路线是云主机沿用当前 Python 进程和 SQLite；改造较少，但用户本次选择先尝试托管。Pages 静态演示可以独立发布，只适合看效果，不能作为本设计的交付验收。Cloudflare Containers 涉及不同运行和计费条件，未纳入本次免费试用方案，不自动启用。

| 组件 | 责任与边界 |
| --- | --- |
| 静态资源 | 托管现有 ES 模块、CSS、Logo；排除源码目录以外的数据库、上传、备份、口令文件和学生附件。 |
| Python Worker | 接收 HTTP 请求，验证权限与字段，调用各领域业务；保持现有金额单位为整数分及网页消费的响应契约。 |
| D1 | 保存账户、商品、上传元数据、订单、账本、聊天、工单、审计、头像与资料版本等持久数据。所有查询需要明确限制与必要索引。 |
| R2 | 保存已校验的商品照片、头像、受保护凭证及备份产物。数据库保存对象键，不能再保存服务器绝对路径。 |
| 定时触发 | 按计划调用有幂等保障的超时与自动收货逻辑。首版按分钟检查，页面说明调度可能有延迟，不承诺精确到秒。 |

## 代码组织和接口兼容

部署入口与资源配置集中放在 `deploy/cloudflare/`，不能把所有业务堆到单个 Worker 文件。数据库、媒体、调度的 Cloudflare 实现作为 `Backend mission/app/core/` 或对应领域下的适配模块，商品、交易、账号、客服仍各自负责本领域规则。

必须显式处理 D1 / R2 的异步调用。当前同步 `tx()` 与 `connection.execute()` 不能通过假装同步的包装器直接套在 Worker 上。实施前的计划需要逐个标明涉及的 service、路由以及测试；修改共享接口时同步维护本地适配器，使本地 Python 试用版仍可运行。不得在两个独立后端中长期复制两套订单与账本规则。

网页和小程序现有 API 契约先保持兼容，包括最新用户资料、头像接口的错误状态与版本校验。任何接口格式统一另行实施，不与本轮托管迁移同时强行变更。

## 必须先验证的兼容性

在选定的 Workers Python 运行环境中，用隔离探针验证 PBKDF2、随机数、摘要、Pillow 导入、图片尺寸检查、重编码和元数据处理。记录真实运行时版本和资源消耗。

保持当前密码算法强度及旧摘要兼容，不能为满足免费额度减少哈希轮数、改成弱摘要或保存明文。若免费执行限制无法支持认证或图片处理，要向用户说明实测结果与成本选项，不能先宣称全功能永久免费。

本轮环境无法访问 Cloudflare 官方文档和 API（代理返回 403），因此未实时确认产品限制；不能把此前引用的通用免费额度视为当前账号的已核实配额。

## 交易、退款和权限

不能用 D1 多次独立网络请求模拟 SQLite 的交互事务。需基于平台实际支持的原子批处理、条件写入与唯一约束设计订单创建、库存预留、状态流转和账本写入，并用真实 D1 环境测试失败回滚。未证明原子性前不得开放下单。

验收至少覆盖不同请求键争抢同一商品只有一张有效订单；同请求键重试返回同一结果；付款、退款、结算及冲回不重复入账；部分退款保持可对账；售后暂停自动结算；员工不能处理利益冲突工单。定时任务重试不能重复退款或结算。

首次公开试用前需处理已复现的“封禁卖家取消预留订单后商品重新回到在售”问题，并在商品流、库存释放和下单时核验卖家可交易状态。本机草稿、通知主动更新等其他问题继续按测试清单单独安排，不因部署隐去。

平台角色、群角色保持分离；普通注册不能传入管理角色。管理员通过操作者的安全初始化流程创建，不提供共享默认密码或公开初始化接口。

## 图片、私密数据与备份

保留图片格式、尺寸、5MB 上限、上传所有权与重复图片校验。商品公开图和头像可通过同源媒体路由读取；私密凭证只能由所属账号和有权限的人员读取，不能因 R2 对象键可猜而公开。R2 访问凭据不出现在网页、小程序或 GitHub。

旧的本地 `_backup()` 不能作为 D1/R2 备份实现。使用平台支持的数据库导出 / 恢复能力，并保存对应媒体清单与对象；在隔离环境演练恢复与权限核对。不要把含账号数据的备份放在公开静态资源或匿名下载地址。

## 额度与运行

仅准备免费计划范围内的独立试用资源。未获明确授权不升级付费计划、启用额外收费产品或绑定付款方式。若 R2 开通要求账单操作，由用户在控制台自行核对。

聊天维持当前接口，首版针对可见会话按需请求，页面隐藏时降低 / 停止刷新，避免用高频全量轮询消耗 Workers 与 D1 额度。订单提醒刷新频率、列表分页与数据库查询行数需要纳入实际测试；不能承诺免费额度足够全学院使用。

启用必要的错误日志、用量观察和限速；日志不记录密码、恢复码、令牌、完整收货地址或私聊正文。免费额度触顶时提供明确的服务提示，不丢弃或伪造已提交订单结果。

## 账号授权与网络前提

当前机器未检测到 `CLOUDFLARE_*` / `CF_*` / `WRANGLER_*` 变量，也没有可用的本机 Wrangler 登录配置；Wrangler 4.151.1 的 `whoami` 确认未登录。

环境配置草稿已登记：

- 非秘密变量 `CLOUDFLARE_ACCOUNT_ID`；
- 秘密 `CLOUDFLARE_API_TOKEN`，只注入到 `api.cloudflare.com`；
- 网络域名 `api.cloudflare.com`、`developers.cloudflare.com`、`dash.cloudflare.com`、`*.workers.dev`、`*.pages.dev`。

用户在环境设置安全填写，不在聊天里发送值。Token 仅授权所选账户必要的 Workers Scripts、D1 和 R2 管理权限，部署不需要 Global API Key。若不使用环境授权，可在用户自己电脑通过 Wrangler 浏览器登录，再按经过审阅的配置操作；不能把 GitHub 已授权误当成 Cloudflare 已授权。

保存草稿不代表授权已注入或网络规则已生效。先验证账号访问，再创建带明确试用名称的独立资源，不修改用户既有网站 / 数据库 / DNS，不自动迁移本机真实数据。

## 交付和验收标准

1. 提供账户归属明确的 HTTPS 地址，以及部署版本、资源名称、实际计划与用量检查方式。
2. 两个独立账号、不同设备访问同一地址：发布三图、收藏、合并下单、模拟付款、交接、收货、售后退款、客服审核与管理员下架均可操作；验证角色隔离。
3. Worker 重启 / 重新部署后，账号、图片、商品、订单、聊天和工单仍存在；任何实例都不依赖本机文件持久化。
4. 在真实 D1/R2 测试争抢、重试、事务失败、定时任务幂等、备份恢复，以及图片私密权限。测试报告区分本地模拟和远程实测。
5. 在广州校园实际网络验证注册、上传和浏览延迟 / 可达性；未测前不承诺稳定访问。
6. 交付可重复的构建、迁移、部署与回滚步骤；无密钥入库。回滚前端 / Worker 版本不能覆盖已经产生的业务数据。

本轮只完成可部署性与授权检查、此设计及静态资源打包 dry-run；**可登录 Worker / D1 / R2 迁移、线上资源创建和真实公网验收均尚未完成**。
