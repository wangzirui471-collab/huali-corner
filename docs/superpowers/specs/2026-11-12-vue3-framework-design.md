# 当前网页版 Vue 3 框架接入设计

用户已指定 Vue 3 + Vite、Vue Router、Pinia，并要求不改变当前页面、样式和功能；本轮「开始重构」授权继续实施这一路线。

## 基线与范围

从 `a36cead19ba6ce5548a6fb6d8e6ed8a748da2e8d` 开始，在已有独立 worktree 的 `refactor/vue3-current-web-20261112` 分支开发。当前 main 没有 AGENTS.md 和十月 AI 接管文件，不从旧分支覆盖。本次只接入框架，不引入 Element Plus 全局样式，不迁移后端和数据，不调用真实账号或模型。

## 方案

采用渐进接入：Vue 的 App / RouterView / 页面适配组件拥有应用生命周期，现有页面函数在稳定的 `#app` DOM 内渲染；Vue 不对这些内部节点做 diff。Vue Router 使用官方 hash history，旧 `#staff` / `#product/1` 链接仍接受，导航规范为 `#/staff` / `#/product/1`；旧读 hash 的位置统一兼容两种形式。权限、错误页、进度和 renderId 过期响应保护继续用原实现。

Pinia 是唯一共享状态实例；旧 `state` 导出指向同一 store，不另建账号或购物车副本。运行时句柄用 shallowRef，普通业务字段保留响应式。不新增凭证持久化。

Vite 负责本机开发、SFC 编译和生产入口构建。现有 CSS、图片、宠物及预编译办公资源原样复制到 dist；开发仅代理 `/api` 和 `/media` 到显式本机地址，禁止远程代理。原 Worker 配置不运行、不改数据绑定。构建目录独立，原网页资源仍保留在源码。

整页改写为 SFC 会扩大模板和事件变更；仅挂载一个空 Vue 实例则不能完成框架接管。以上渐进适配同时满足真实接入和现有页面保持的约束。

## 验收

1. 保留重构前合成登录、HTML401、JSON401和四屏宽 AI 三模式基线。
2. Pinia 唯一状态、购物车账号隔离、运行时句柄和路由前进后退测试。
3. 原测试回归，真实 Vite 开发服务与生产构建页面均能运行。
4. 同一合成 API 下比较原站与构建站的页面 DOM、关键位置、样式和截图；静态 CSS/图片按字节检查。
5. 旧深链接、未知路由、同页刷新、查询参数、慢响应、权限入口、AI 草稿和窗口均检查。不以本机结果冒充微信真机、真实账号或生产发布。
