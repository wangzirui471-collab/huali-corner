# 前端协作规范（给第二位开发者）

> 这份文档是你要遵守的全部约定：在哪写、怎么写、写什么、怎么算完成。
> 有看不懂的先问，不要猜——猜出来的代码返工成本比问一句高十倍。
> 最后更新：2026-10-17

---

## 0. 分工一句话

**你负责「用户端」**（逛、买、卖、订单、个人页），**我负责「平台端与基础设施」**
（客服工作台、管理员工作台、core/、路由、样式系统）。

这样分的唯一目的：**两个人改的文件永不重叠**，就不存在「提交不上去」的问题。
边界见第 2 节的归属表，那是这份文档里最重要的东西。

## 1. 项目是什么

校园二手交易平台原型（`E:\zi\huali-corner-trial`），纯前端是 **原生 ES Module +
单页 hash 路由**，没有框架、没有构建步骤、没有 npm 依赖。
`web 7M/index.html` 直接引 `src/main.js`，浏览器原生加载。

- 后端在 `Backend mission/`，接口前缀 `/api`，**不在你的改动范围**。
- 所有金额单位是「**分**」，展示时才除以 100。
- 演示数据在 `var/`、试用数据在 `var-trial/`，都不进 git。

### 1.1 页面切换性能（2026-10-29 起为硬约束）

线上接口一次往返 0.7–3.0 秒，切页慢几乎全是在等网络。写代码不得让它更慢：

- 页面入口只允许一次串行等待，无依赖请求一律 `Promise.all`。
- 新增页面入口接口必须登记到 `src/core/http.js` 的 `CACHE_RULES`（给 TTL），
  缓存由 `api()` 统一管理：按账号隔离、任何 POST 自动失效，页面不要自建副本。
- 新增 `data-go` 入口要在 `src/main.js` 的 `PAGE_WARM` 登记预热；不能预热的写清原因。
- `/messages`、`/rooms`、`/badges` 等轮询接口禁止缓存。
- 验收口径：同一会话二次进入任一主页面 ≤ 200 ms、命中缓存时页面 0 个 `/api/*` 请求；
  提交说明附“改动前 → 改动后”的实测数字。全文见开发规范 V2.0 第 6.7 节。

### 2.3 共享协调点（**改之前必须在对话里说一声**，改完立刻提交）

这三个文件是接线用的，谁都要偶尔碰，但每次只许做「最小的一行级改动」：

| 文件 | 你可能需要做的 | 规矩 |
|---|---|---|
| `src/router.js` | 注册新路由：import 一行 + `funcs` 里一行 + `AUTH_ROUTES` 加一个词 | 不许动别人的路由项 |
| `src/actions/index.js` | 注册新的 actions 模块：import 一行 + 合并表里加 `...你的模块` | 不许动合并顺序以外的部分 |

**为什么这么严**：这三个文件是所有人的必经之路，谁在里面做「顺手重构」，
谁的冲突就是全站的。

## 3. 编写规范

### 3.1 分层（这个项目的骨架，必须遵守）

```
core/       基础设施：DOM 工具、格式化、状态、HTTP、路由跳转、页面骨架
components/ 可复用组件：表单字段、商品卡、工作台骨架
pages/      页面层：只负责「把 HTML 字符串拼出来交给 shell()」
actions/    事件层：所有 data-action 按钮和表单提交的分发处理
auth/       登录弹窗与守卫
```

**页面不写逻辑，逻辑不碰 DOM 事件。** 一个按钮的点击效果写在 `actions/*.js`，
页面里只放 `data-action="xxx"`。

### 3.2 代码风格

- 每个文件第一行 `'use strict';`，第二行开始是一段**说明这个文件职责与分工的注释**。
- ES Module：只 `import` 用到的；导出用命名导出。
- 模板字符串拼 HTML，统一用反引号；**任何插值进 HTML 都要过 `e()`**：

  ```js
  import { e } from '../core/dom.js';
  `<b>${e(item.title)}</b>`          // ✓
  `<b>${item.title}</b>`             // ✗ XSS：标题里带 <script> 就完了
  ```

- 金额一律 `money(分)`（`core/format.js`），时间一律 `date(秒级时间戳)`。
  **不要手写 `/100` 或 `toLocaleString`**——时区和舍入已经在这两个函数里处理过一次坑。
- 事件处理函数是 `async (button, id) => {}`，出错就 `throw`——
  外层 `actions/index.js` 统一 `toast(err.message)`，你不要自己 try/catch 吞掉。
- 注释写**为什么**，不写**是什么**。`// 遍历列表` 这种注释不要写。

### 3.3 交互约定（全站统一，别自创）

| 要做什么 | 怎么做 |
|---|---|
| 跳转 | `<button data-go="orders">`，**不要** `location.href = ...` |
| 点击行为 | `<button data-action="xxx" data-id="1">`，处理函数注册在 `actions/*.js` 的 `clicks` |
| 表单提交 | `<form id="xxx-form">`，处理函数注册在 `submits`，**表单必须有 id** |
| 弹窗 | `import { modal, closeModal } from '../core/shell.js'` |
| 轻提示 | `toast('已保存')` |
| 请求 | `import { api } from '../core/http.js'`；`api('/orders')` GET，`api('/orders', {...})` POST |

**禁止**：`addEventListener`（页面与组件一律不自己挂监听，全靠 actions/index.js 的
事件委托）、`onclick=` 内联、`document.write`、`innerHTML = 用户输入`。

### 3.4 列表页的筛选

列表筛选走「**行内显隐**」，不要重新 `render()` 整页——整页重画会丢滚动位置、页面闪。
参考 `actions/staff.js` 的 `applyChips` / `applySearch`：行上放
`data-group` / `data-tags` / `data-search`，筛选只改 `hidden`。

## 4. 五条硬规则（违反直接打回）

1. **不许发明接口。** 前端只能调后端已有的 `/api/*`。需要新接口时，先在
   `docs/` 下写一小段契约（路径、参数、返回、错误码），等后端落地再接。
   接口暂时没有的按钮，用一句人话提示（参考 `actions/staff.js` 的 `PENDING` 表），
   不要让用户看到「接口不存在」。
2. **不许重构别人的区域。** 包括但不限于：改 core/ 的函数签名、
   把别人的页面「顺手」迁移到你的风格、改 CSS 变量名。
3. **不许 `git add -A` / `git add .`。** 只 `git add` 你这次真的改了的文件。
   工作区里常有另一个人未提交的改动，一把梭会把半成品卷进你的提交。
4. **不许提交口令、密钥、真实手机号。** 仓库是公开的。
5. **改动必须过自检**（见第 7 节），自检不过不许 push。

## 5. 动手前的三查（每次开工都做）

```bat
cd E:\zi\huali-corner-trial
git switch dev/frontend       :: 0. 切到自己的副分支（后端换 dev/backend）
git pull --rebase             :: 1. 先拉，别在旧基线上写
git status --short            :: 2. 看工作区干不干净；有别人的未提交改动就不要动那些文件
git log --oneline -3          :: 3. 看最近谁改了什么，避免重复造轮子
```

这个仓库**经常有两个人同时在一个工作区写代码**。文件被别人正在写时
（`git status` 里有它、或改动时间就在刚才），你跳开，写你自己的文件。

## 6. 本轮要完成的功能（工作包）

按顺序做，每个包独立提交。范围都刻意限制在你的领地内。

### 工作包 A：改单体验补齐（订单）

需求文档 §9：改单目前只支持改时间地点，下面三个字段后端已支持但前端没暴露——

- `product_ids`：传**保留**的商品 id 列表，未保留的会被移除（要在界面上能勾选）；
  **仅买家可改**，卖家界面不出现这项；
- `delivery`：改成送货会重算送货费；
- `address`：送货时必填，改成自提时自动清空。

位置：`pages/orders.js` + `actions/change.js` + `actions/trade.js`。
**验收**：三种字段都能在改单弹窗里改（卖家只能改时间）；送货不填地址被前端拦下并提示；
自提时地址输入框隐藏且提交的 `address` 为空。

### 工作包 B：发布草稿与自动保存

需求文档 §7.5：发布页填一半刷新，内容全丢。

- 草稿存 `localStorage`，key 用 **`hc-draft-publish-<用户id>`**——
  存储键全站统一 `hc-` 前缀（见 `core/state.js` 的 `hc-cart-<id>`），
  且必须带用户 id：同一台浏览器换账号登录，不能把 A 的草稿恢复给 B；
- 字段变化即保存（防抖 500ms）；
- 进入发布页时若有草稿，顶部出一条「恢复上次草稿？」提示条；
- 发布成功后清掉草稿；用户主动「放弃草稿」也要能清。

位置：`pages/publish.js` + `actions/catalog.js`。
**验收**：填一半刷新不丢；换账号看不到别人的草稿；恢复后字段齐全；
发布成功后 localStorage 里不再有草稿；
**不含图片**（图片上传有配额，草稿只存文本字段与已上传图片的 id）。

### 工作包 C：你名下文件的品牌名替换

需求文档 §97：全站从「华立转角」改为「转角」。

- **只改你名下文件**里的用户可见文案（页面标题、空态文案、按钮、aria-label）；
- `core/shell.js`、`index.html`、`market.css`、logo 图片里的由我来改，你别碰；
- 不改：CSS 类名、localStorage key、接口字段、文件名、注释里的项目代号。

**验收**：`grep -rn "华立转角" web 7M/src/pages/ web 7M/src/actions/` 在你的领地里为 0，
页面无一处残留；不许因为改名引入任何行为变化。

## 8. Git 流程

仓库只有三个分支，各司其职：

| 分支 | 定位 | 谁推 |
|---|---|---|
| `master` | 主分支 · 生产级（GitHub 默认分支） | 只从开发分支合并进来，不直接写 |
| `dev/frontend` | 副分支 · 开发级 | 负责前端的人 |
| `dev/backend` | 副分支 · 开发级 | 负责后端的人 |

日常在**自己的副分支**上写和推：

```bat
git switch dev/frontend                     :: 后端换 dev/backend
git pull --rebase                           :: 先对齐自己的副分支，别在旧基线上写
:: ...写代码...
git status --short                          :: 确认你要提交的就是你改的那几个
git add web 7M/src/pages/orders.js web 7M/src/actions/change.js
git commit        :: 用上面的格式
git push origin dev/frontend
```

要发布时，把自己的副分支合并进 `master`：

```bat
git switch master
git pull --rebase origin master
git merge --no-ff dev/frontend              :: 保留「这是一次发布」的边界
git push origin master
```

- 为什么不直接在 master 上做：两个人改同一屏时，线性历史会把两次无关的改动压成
  一串，要回退只能整串回退。副分支给每个人一个「可以先推、不影响对方」的缓冲，
  **合并进 master 才是发布点**。
- 方向永远是 **副分支 → master**。不要为了「同步」把 master 合回副分支，那会在
  副分支上堆一批无意义的合并提交；要同步就 `git pull --rebase origin dev/<你的分支>`。
- push 被拒不要 `--force`，先 `pull --rebase`。
- 提交失败/冲突时停下来问，不要自己想办法绕。

**2026-10-17 分支收口**：原来 8 个 `feat/*`、`fix/*`、`ops/*` 分支已合并或已过期，
收成上面三支。删除前逐个打了 `archive/<原分支名>` 的 tag，要翻旧代码直接
`git checkout archive/feat/layered-completion`；`git tag -l "archive/*"` 看全部。

## 9. 不确定的时候

- **接口够不够用**：看 `Backend mission/server.py` 的路由表，那是一份真实清单。
- **某个交互该长什么样**：看 `pages/staff.js` + `actions/staff.js`，那是全站最新、
  注释最全的一套，照着它的结构写。
- **样式**：`market.css` 顶部 `:root` 是设计令牌（颜色/圆角/阴影），只用令牌不写死色值；
  你需要新样式时，在自己的页面里用现有类，实在要加 CSS 就**追加到文件末尾并注明分区号**。
- **都不确定**：在对话里问。写错方向的一小时，比问问题的十秒钟贵得多。
