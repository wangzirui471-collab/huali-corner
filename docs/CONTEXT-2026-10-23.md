### 关键设计取舍

1. **并发默认 1，不装能扛**。8G 显存跑 7B Q4，两个请求只会互相拖慢。排满 3 个后
   45 秒内没轮到就返回「忙」，前端显示「排队中 · 摘录」，绝不把客户挂在转圈上。
2. **模型不可用 ≠ 服务不可用**。没有 Ollama、没有模型、没 Key、超时、排队满，
   一律降级成知识库原文摘录并给出原因，客服页面永远能打开。
3. **半截推理不是答案**。R1 被 `num_predict` 截断时只剩 ` thinking` 里的自我怀疑，
   现在判为「无答案」并退回原文；以前会原样发给客户。
4. **客户本地、办公云端可以拆**。`HC_AI_OWNER_PROVIDER=api` 让 L1 的批量草稿走云端，
   客户问答继续留在本机，互不抢显存。

## 3. 现状与风险

- **本机没有 NVIDIA 显卡、也没装 Ollama**（`nvidia-smi` 不存在），所以真模型只在
  假服务上验证过调用链；在 RTX 4060 8G 上的真实速度需在你那台机器上用 `preflight.py --ask`
  跑一次确认（预期 10–20 秒/次）。
- 线上 Cloudflare 侧**跑不了开源权重**：Worker 托管不了 7B/14B，线上仍走
  `deepseek-flash`（所有者可用 `HC_AI_MODEL_OWNER` 指定更强模型）。
  本地模型与线上 API 的规则是两份副本，改规则要同步（见 `docs/CONTEXT-2026-10-22.md` 第 3 节）。
  注意：**工作模式已经上线**（见第 6 节），「线上只有办公助手」这句话已过期。
- Worker 的 `/api/config` 还没有 `ai_local` 字段；前端缺这个字段时按云端文案处理，
  行为正确，但为了字段一致可以在下次部署时补 `'ai_local': False`。
- 本机模式不解决公网访问、备案、内容审核，只解决「数据不出机器」。

## 5. 事故记录：整站 500「服务暂不可用」（14:45 发现，15:05 修复）

**现象**：线上首页整屏「服务暂不可用：服务内部错误」；`/api/config` 200，
但 `/api/health`（只执行 `SELECT 1`）、`/api/products`、`/api/product` 全部 500；
登录弹窗提交后底部 toast「服务内部错误」。

**定位路径**（值得复用）：
1. `/api/products?category=书籍` 返回 200 `[]` → 一度以为是数据问题；
   实际是**命中了 KV 缓存**（键含 query），缓存里有旧的空数组，绕过了坏路径。
   教训：判断「接口是不是好的」别用可能被缓存的 URL。
2. `wrangler tail --format json` 里 `outcome: ok`、`exceptions: []` —— 栈被
   `http.py` 的 `guard()` 静默吞掉，线上完全看不到原因。
3. 建一个与线上同提交的干净 worktree，`wrangler dev` 本地复现；
   临时在 `guard()` 里 `traceback.print_exc()` 才拿到栈。

**根因**：`wrangler.jsonc` 加了 `disable_python_external_sdk`（改用平台内置
Python SDK）后，D1 返回值形态变了，`app/cloudflare/d1.py` 的两处假设同时失效：

```text
dict(row)        → TypeError: 'pyodide.ffi.JsProxy' object is not iterable
dict(JsNull)     → TypeError: 'JsNull' object is not iterable
```

- 旧外部 SDK 会把 D1 行**转成 dict**、把空行转成 **None**；
- 平台 SDK 直接给裸 `JsProxy` / `JsNull`。

于是 `all/first/scalar` 全炸（整站 500），空行路径也炸
（商品不存在本该 404、登录失败本该 401，全变 500）。

**修复（提交 `5308b79` + `61c9a60`）**：
- `d1.py` 新增 `_py / _is_null / _as_list`，读路径与 `meta.changes`、
  `used_bytes`、`batch` 全部先转 Python 对象，**新旧两种 SDK 都能跑**；
- `http.py` 的 `guard()` 把未预期异常的栈打进 Worker 日志（只进
  `wrangler tail`，不回客户端）——这次就是被静默吞掉才拖了时间；
- 新增 `tests/test_cloudflare_d1_rows.py`（7 项）：用假绑定模拟
  `JsProxy` / `JsNull` / dict 三种形态，防回归。

**处置**：先 `wrangler rollback d45cc213` 止血（13:38 的已验证版本），
再部署修复版 `d0aadde3`。

**以后要记住的两条**：
1. **换运行时/SDK 版本后，先在干净 worktree 里跑一轮真实接口**，
   不能只看单测——单测里的 fake 数据库返回的是 Python dict，恰好把这类
   形态差异全部掩盖掉。
2. **边界处的 `except Exception` 必须把栈打进日志**，否则线上只剩一句
   「服务内部错误」，tail 里连 exceptions 都是空的。

## 6. L1 所有者 + 工作模式（本地 → 线上，今天的主线）

### 6.1 owner（L1）：参照 GitLab Owner 模型

- 层级：`user < support < admin < developer < owner`，owner 可任免 developer 及以下。
- **防锁死**：owner 账号不能被后台降级/停用（本地与 D1 双端都有守卫），
  只能运维直接改库；工作模式里也拒绝把 owner 作为操作目标。
- 管理台、角色筛选、前端 `isOwner` 全部接上；`day`（id=2）已设为 owner 并写了审计。

### 6.2 办公助手 `/api/ai/office`（提交 `b70d0de`）

- 只读快照：待处理工单、处理中、用户、24h 活跃、在售商品、24h 订单、最近审计。
- 起草客服公告/回复；所有者可用 `HC_AI_MODEL_OWNER` 指定更强模型。
- 不可逆操作参照 LangGraph HITL：模型只出 proposal，owner 在浏览器二次确认
  才执行，后端复查 owner 身份并写审计。**模型永远不直接写库。**

### 6.3 工作模式工具台 `/api/ai/work/*`

- 接口四个：`tools`（GET 目录）、`chat`（一句话）、`call`（直调工具）、`confirm`（执行）。
- **37 个工具（20 读 + 17 写）**，本地 `app/support/work.py` 与线上
  `app/cloudflare/work_mode.py` 目录逐项一致（有脚本可比对，无差异）。
- 写工具只出确认卡：本地 HMAC 令牌（10 分钟），线上 `ai_office_jobs` 作业行。
- 读工具确定性 SQL，名单/手机号不交给模型"编"；手机号默认打码，
  `reveal=true` 看全号并写 `pii_view`，看聊天记录写 `chat_view`。
- **多步（`dee038a`）**：ReAct 最多 3 步（规划 → 执行读工具 → 结果回填 → 再规划），
  写工具即中断出卡；`product_bulk_moderate` 可按关键词/分类/卖家批量下架或恢复（≤50 件）。
- **评测集** `tests/eval_work_agent.py`：9 条 golden case，验证工具选择 + 写操作只出 proposal，
  用固定 planner 桩，不依赖网络和模型；当前 **9/9**。
- 设计说明见 `docs/WORK-MODE.md`、`docs/AGENT-DESIGN.md`（借鉴 ReAct / LangGraph HITL /
  OpenAI 工具 schema / DSPy few-shot / Ragas 评测思路，明确列出没采用的方案）。

### 6.4 D1 移植（提交 `b00cdf8` + `a11c401`）

| | 本地（SQLite） | 线上（D1） |
| --- | --- | --- |
| 提案载体 | HMAC token（进程内密钥） | `ai_office_jobs` 行，作业号即 token |
| 确认校验 | 验签 + 过期 + uid | 同 batch 复查 actor/state/参数 + owner 仍活跃 |
| 执行原子性 | 同步事务 | `guarded_batch`，守卫不满足整批回滚 |
| 重复确认 | token 单次 | 幂等：返回同一回执 + `repeat: true` |

几个线上才有的坑（都已处理）：
- `ai_quota` 有 2 秒间隔，多步循环第二步必 429 → 工作模式改用 `_work_quota`（只按天封顶）。
- 守卫拼接不能写 `EXISTS((SELECT …) AND (SELECT …))`，作业复查要作为子查询挂在
  WHERE 后面，否则 SQLite 直接语法错。
- 批量 id 集合用 `json_each` 传（D1 单语句绑定参数上限 100）。
- `backup` 复用 `cf_staff_backup_archive`，管理台下载与一句话备份同一套打包；
  对象存 `backups/` 私有前缀，不走图片重编码。

**演示商品闭环**：`demo_generate`（只出预览，不写库）→ 后端把预览项直接注入
`demo_publish`（不经模型转抄）→ 确认卡里列出标题/价格/成色 → 确认后批量入库（virtual）。
模型不可用时规则兜底也能走完整条链路（能解析「发布 3 件…」的数量）。
