# 首页管理下架、订单进度与模拟退款记录

日期：2026-10-17（北京时间）。这是可登录试用版的网页与后端增量，不包含公网部署或真实微信退款。

## 1. 首页下架在哪里

原入口只在商品详情“举报商品”旁，首页卡片没有放置。这次补到首页及使用同一商品卡片的列表：管理员/客服登录后，每张在售商品卡片底部都有红色“下架商品”。普通用户和未登录用户没有此按钮；已预留、已售出及已下架商品不提供直接管理下架。

点击后填写原因并确认；取消不会下架。操作复用后端原有权限、状态、出价失效、卖家通知、审计机制，不删除历史记录、不自动扣分。不是隐藏卡片的前端假操作，刷新或换账号查询也会看到服务器已下架的结果。

如果仍看不到，先核对：是不是完整新版、是不是可登录试用版（静态公开演示没有管理功能）、是否登录原管理员或客服账号、商品是否仍在售。普通注册不会自动得到管理员角色。

## 2. 订单页的四项进度

在“我的订单”每张订单卡里展示：订单进度、交付进度、售后进度、模拟资金。来源是既有订单、交接时间、退款工单和账务流水；不改原状态枚举，也不新增四套状态机。

- 待付款、待卖家确认时间、卖家标记已交付、买家核对交接分开展示。
- 只有买家核对交接才有自动收货起点；售后处理中暂停倒计时和自动结算。
- 完成订单后申请售后，不抹掉原买家收货历史。
- 全额退款、部分退款、已结算和仍待收货的模拟金额分开展示；流水不平衡时明确提示管理员核对，不展示虚构成功。
- 所有投影只读，不因打开订单页产生支付、退款、结算或库存变化。

接口兼容：订单 DTO 增加 `progress`，原订单字段、`items`、`ledger`、`changes`、`notes` 均保留；原小程序可继续使用旧字段，新的四项卡片本批只接入网页。

## 3. 退款执行记录

在原售后工单显示审核、模拟执行、流水核对。新增 `support/refund_execution.py` 和 `refund_executions` 表，启动时增量创建；不删除原数据库、订单或工单。

成功记录与原退款流水、订单/商品更新、工单结案在同一事务提交。注入执行异常时原事务回滚，再记录失败和审计，管理员核对后可重试；成功后重复提交不多退，明确改变已执行金额返回409。

记录保留当前执行结果、金额、最后执行人、尝试次数及时间，失败有固定错误码，原失败还留审计；客户端不返回异常堆栈或内部错误字符串。未通过权限、金额和退货条件的请求不会伪造一条执行失败。旧工单已有退款但没有新记录时显示“历史流水”，不补造时间。

边界：这是同步模拟执行追踪，不是机构异步支付队列。进程被强制结束或数据库不可写时，不能保证失败记录能另行持久化；但成功记录与资金事务同生同灭。审批后独立待执行队列、真实机构回执和逐件退款仍待后续任务。

## 4. 更新已有账号数据

1. 先停止旧服务，将完整原数据目录（通常为 `var-trial/`）备份到另一个安全位置。
2. 完整新版解压到一个新目录，保留 `Backend mission/`、`web 7M/src/`、资源和启动脚本的结构。不能只替换 `server.py`。
3. 先复制原数据到测试副本，用新版 `--trial --data` 指向该副本验证账号、订单、图片及账务；确认后再安排切换原目录。
4. 示例命令中的路径要换成实际完整路径：

```powershell
cd "新版解压目录"
python "Backend mission/server.py" --trial --port 8081 --data "原试用数据目录的完整路径"
```

保持终端开启，浏览器打开 `http://127.0.0.1:8081/#home`，用原管理员/客服账号登录，再按 Ctrl+F5。若误用全新空数据目录启动，自然找不到原管理员；应核对目录，不要因此删除账号或手改角色。

迁移会创建新表，不能靠旧库覆盖新版运行后的数据来回滚，否则会丢失新增订单。更新包不带任何真实账号、密码、数据库或上传照片。
