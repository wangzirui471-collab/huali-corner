# 第一章 架构与运行环境

## 1.1 双运行时（本版最重要的变化）

转角现在有**两套后端运行时**，业务规则必须保持一致：

| 运行时 | 入口 | 数据 | 用途 |
| --- | --- | --- | --- |
| 本地 Python | `Backend mission/server.py` | SQLite 默认；`HC_DB` 可切 MySQL | 开发、本机试用、数据备份 |
| Cloudflare Python Worker | `Backend mission/worker.py` → `app/cloudflare/worker.py` | D1 + R2 + Assets | 线上试用（`*.workers.dev`） |

**Cloudflare 运行时（Pyodide）的硬限制（实测，不得假设普通 Linux 能力）：**

- **没有线程**：`threading.Thread.start()` 抛 `RuntimeError`；不要写依赖后台线程的代码。
- **没有真实 `sqlite3` 持久化**：`sqlite3` 可 import，但只是内存桩；线上必须走 D1。
- **没有 `hashlib.pbkdf2_hmac` / `hashlib.scrypt`**；WebCrypto PBKDF2 生产上限 10 万轮；pycryptodome wasm 会 1105 内存超限。
  - 结论：**600000 轮 PBKDF2 放浏览器端做**，服务端只收 `{salt, rounds, digest}`；`app/cloudflare/crypto.py` 用纯 `hashlib.sha256` 自实现 PBKDF2，仅用于校验/旧数据兼容。
- **Pillow 12.2.0**（12.3.0 无 wasm32 轮子）；图片处理可用，但注意内存。
- **D1 事务原语是 `batch()`**：一批语句原子执行；用 `guarded_batch` 做“守卫 SELECT + 写入”的原子校验。
- **未注册的 `/api/*` 返回 501**（`api.py` 的兜底），不是 404；新增接口必须同时加路由，否则线上表现为“该接口尚未在试用版开放”。

## 1.2 后端分层（当前保持）

```
Backend mission/
├── server.py                 本地 HTTP 服务与路由分发（不承载复杂业务）
├── worker.py                 Cloudflare 入口薄壳
├── manage_trial.py           本机账号管理命令
├── requirements.txt
├── wrangler.jsonc
├── python_modules/           Worker 依赖（gitignore，部署时需存在）
└── app/
    ├── market.py             Market 组合类（多继承拼装领域服务）
    ├── seed.py               演示数据
    ├── core/                 config / database / errors
    ├── account/              账号、资料、头像、信誉
    ├── catalog/              商品、发布、三图、搜索、上下架
    ├── trade/                订单、交付、模拟账务
    ├── community/            帖子、评论、群聊、私聊、好友门禁
    ├── support/              工单、客服、档案、信誉处罚
    ├── staff/                客服工作台
    ├── moderation/           敏感词与内容处置
    ├── ops/                  对账、备份
    └── cloudflare/           D1/R2/Worker 适配层（只做运行时适配，不放业务规则）
```

**必须：**

- `server.py` 只做 HTTP 解析、鉴权入口和路由分发；新增业务进入对应领域模块。
- `app/cloudflare/` 只放运行时适配（D1、R2、crypto、http、sessions），不复制一套业务规则。
- 本地与线上的业务语义必须一致；新增接口要在两边同时实现（本地 `server.py` + `app/cloudflare/*_api.py`）。

## 1.3 数据层

| 引擎 | 入口 | 关键约定 |
| --- | --- | --- |
| SQLite（默认） | `var-trial/market.sqlite3` | 删除日志模式（非 WAL）；`_WRITE = RLock()` 串行化写事务；金额整数分 |
| MySQL（可选） | `HC_DB=mysql://user:pass@host:port/db` | 连接池；**`autocommit=True`**（否则读连接快照看不到刚提交的行）；SQL 方言改写 |
| D1（线上） | `DB` 绑定 | 30 张表；`batch()` 原子；`autocommit` 由 D1 管理；schema 全部 `CREATE TABLE IF NOT EXISTS` |

**必须：**

- 路径只从 `app/core/config.py` 取（`ROOT` / `WEB` / `ASSETS` / `data_dir(trial)`），不写 `Path(__file__).parent/...`。
- `var/`（演示）与 `var-trial/`（真实）严格隔离；**禁止删除或覆盖 `var-trial/`**。
- D1 schema 变更必须幂等、可重复执行；禁止 `DROP`/`DELETE` 式迁移。
- MySQL 迁移脚本、D1 schema、SQLite DDL 三处结构要能对上；改一处必须同步检查另外两处。

## 1.4 前端分层（当前保持）

```
web 7M/
├── index.html
├── market.css / styles.css / user-center.css / credit.css
└── src/
    ├── main.js / router.js
    ├── core/        dom format state http nav shell asset roles
    ├── components/  forms product-card user-profile user-avatar
    ├── pages/       home product publish cart orders listings
    │                me community forum messages support
    │                credit staff admin-desk dossier
    ├── auth/        login
    └── actions/     index(事件委托分发) ui catalog trade social
                     support account staff admin user-profile change
```

**硬约束：**

1. 全局共享状态只在 `src/core/state.js`；不允许新增跨模块状态副本或大量 `window.xxx`。
2. `router.js` 与 `pages/*` 不得互相 import（会成环）；需要 `render()`/`go()` 时用 `core/nav.js`。
3. 页面只负责渲染；交互放 `actions/*`，由 `actions/index.js` 合并分发。
4. 新增页面要同时检查：路由表、登录守卫、底部/顶部导航入口。
5. 复用现有 CSS 令牌；页面级样式加作用域（如 `.uc-`、`.dossier-`），不覆盖全站。

# 第二章 分支、提交与协作

## 2.1 分支职责（以 `docs/BRANCHING.md` 为准）

| 分支 | 用途 | 规则 |
| --- | --- | --- |
| `main` | 稳定/可发布 | 只接受 `release/*` 合并；不直接提交 |
| `release/2026-10-trial` | 2026-10 校园试用集成分支 | 当前发布分支；功能合并到这里，验证后再进 `main` |
| `feature/<模块>-<描述>` | 新功能 | 从 `release/2026-10-trial` 切出，PR 回合 |
| `fix/<模块>-<描述>` | 缺陷修复 | 同上；不要再用 `fix/f01-*` 装整批迭代 |

**必须：**

- 不为迎合模板把 `main` 改名 `master`，或强推共享分支。
- 公开分支不改写历史；合并前比较目标分支并解决冲突。
- 旧的 `fix/f01-banned-seller-release` 保留作回滚备份，`main` 合并后再删。

## 2.2 里程碑 tag

- `milestone/2026-10-auth-session|friends|forum|support|admin-dossier|product-detail|router`
- 发布点：`v2026.10-trial`
- 部署只从**干净、已打 tag** 的提交；前端资源与 Worker 必须同一次 `wrangler deploy`。

## 2.3 提交规范

采用 `type(scope): 描述`：

- 类型：`feat`、`fix`、`refactor`、`docs`、`test`、`style`、`build`、`ci`、`chore`。
- 一个提交一个主题；相关业务、前端、测试、文档可一起提交；无关需求不混入。
- 示例：`feat(support): 客服会话不进聊天列表`、`fix(auth): 网络失败不清除有效会话`。
- 审查说明包含：问题与结果、关键规则、兼容/数据影响、实际验证、剩余限制。禁止只写“优化代码/测试通过”。

## 2.4 并行会话隔离（重要，已踩坑）

工作区可能有**另一个会话/开发者**的未提交改动。**必须：**

1. 提交前 `git status` 看清文件；只 `git add` 本次自己的文件，**禁止 `git add -A`**。
2. 部署时若工作区有他人未完成改动，用**干净 worktree** 部署：
   ```bash
   git worktree add <tmp> <commit>
   cp -r "Backend mission/python_modules" "<tmp>/Backend mission/"
   cd "<tmp>/Backend mission" && wrangler deploy
   git worktree remove --force <tmp>
   ```
3. 不清理、不 stash、不覆盖他人的未提交工作；确需处理先沟通。

## 2.5 需求变更

用户已明确的常规实现细节可按确认范围推进；涉及**真实收费、对外发布、数据删除、破坏性迁移、未确认业务规则**时，先出方案和可审阅结果，再确认变更。不能把每个小修复都变成审批流程。

# 第三章 命名与接口

## 3.1 命名词典

| 场景 | 规则 | 示例 |
| --- | --- | --- |
| Python 文件/函数/变量 | `snake_case` | `moderate_product`、`ticket_id` |
| Python 类 | `PascalCase` | `CatalogModeration` |
| 常量 | `UPPER_SNAKE_CASE` | `MAX_UPLOAD_BYTES` |
| 网页文件/CSS 类 | 多词中横线、领域清晰 | `admin-desk.js`、`staff-navigation` |
| JavaScript 变量/函数 | `camelCase` | `ticketId`、`loadOrders` |
| JSON/数据库新增字段 | `snake_case` | `seller_id`、`created_at` |
| 布尔值 | `is_/has_/can_`；JS 本地驼峰 | `is_active`、`can_edit`、`hasUnread` |

业务术语统一：`user`、`product`、`order`、`ticket`、`post`、`room`、`notification`、`credit`、`ledger`、`dossier`。不要为同一实体新增 `goods/item` 等近义名。角色/状态/类目用固定机器值，中文只负责展示。

## 3.2 API 现状

- 本地 `server.py` 约 **99 个** `/api/` 路由；Cloudflare 约 **94 个** 唯一路径，两边语义必须对齐。
- 现有合同保持：`/api/products` 是数组；错误常用 `{"error": "..."}`；尚未全站统一封套。
- **前端 `api()` 必须先看 `Content-Type`**：非 JSON 抛 `INVALID_API_RESPONSE`，不得无条件 `res.json()`；否则 HTML 错误页会变成 `Unexpected token '<'`。
- **未注册的 `/api/*` 返回 501**（“该接口尚未在试用版开放”）；新增接口必须同时加路由并在线上验证。
- 静态资源与 SPA 回退交给 Assets；`run_worker_first` 只含 `/api/*`、`/media/*`。

## 3.3 状态码与错误

| HTTP | 语义 | 示例 |
| --- | --- | --- |
| 200/201 | 查询/动作成功、创建成功 | 下架成功、新建草稿 |
| 400 | 参数/格式不合法 | 理由缺失、金额单位不合法 |
| 401 | 无有效登录会话 | 令牌过期；网络失败不能冒充 |
| 403 | 已登录但无权 | 普通用户调用管理下架 |
| 404 | 不存在或按权限不披露 | 不可见私密资源 |
| 409 | 状态/版本冲突 | 已被预订、资料版本过时 |
| 429 | 频率受限 | 带重试说明 |
| 500 | 未预期异常 | 用户只见通用提示，不返回堆栈 |
| 501 | 接口未在试用版开放 | 线上 Worker 未注册该路由 |

**禁止：** 把业务失败伪装成 HTTP 200；把 401 当成网络错误；把 501 当成“页面不存在”。

## 3.4 字段类型

- 金额：数据库与接口用**整数分**（`price`、`total` 等现有字段保持）；新增字段建议 `*_cents`；禁止 `float * 100` 后截断。
- 时间：现有接口用秒级时间戳；新增接口建议 UTC ISO 8601（`created_at`），界面按 `Asia/Shanghai` 展示；不得混用秒/毫秒。
- ID：用户/商品/订单/工单保持数字；上传/草稿等不透明 ID 用字符串，不改主键类型。
- 布尔：JSON 用 `true/false`；缺失/null/空串语义在合同中写明；更新请求不传字段默认保留原值。
- 未声明字段不得成为越权入口（如 `role`、`score`）；普通注册请求体中的提权字段必须被忽略。

## 3.5 分页

- 列表统一 `items + page_info`（新接口）；商品流/消息可用 cursor，管理列表可用 offset。
- 游标不透明、绑定筛选与排序；稳定排序必须有唯一键兜底。
- 分页上限受控；禁止全量读入内存再切片。

# 第四章 编码规范

## 4.1 Python

- 4 空格缩进、UTF-8、导入分组；新逻辑不压成巨型单行，不用分号堆多条业务语句。
- 关键入参与返回应有类型标注或 DTO/TypedDict/dataclass；不用无字段说明的任意 dict 穿层。
- 函数单一职责；约 50 行后检查拆分，超过约 100 行或多职责应说明原因。
- 注释说明业务依据、风险、单位与“为什么”；关键服务写 docstring；修改历史交给 Git。
- **禁止吞异常后假装成功**；非关键降级必须有边界与说明。
- 本地运行：系统 Python 3.8 有 PIL/pymysql；`.venv-trial` 为项目隔离环境；托管 3.13 没有 PIL，不能直接跑后端。

## 4.2 JavaScript / HTML / CSS

- `const/let`、严格比较、`async/await`、模板字符串、语句分号；内部变量 camelCase。
- 网络/提交错误在边界处理；捕获后必须处理、转译、重抛或说明降级，不能无声丢失。
- 独立读取可并行；有依赖的请求、写操作按顺序；提交防重复；重要请求有超时与重试语义。
- 异步操作记录原会话/账号与页面代次；晚返回结果不能覆盖新账号、较新草稿或新页面。
- 动态文本进入 HTML 必须转义（`e()`）；URL/资源 ID/协议校验；禁止 `eval`、内联事件、不受控 HTML。
- 语义化标签、表单 label、图标按钮有可读名称、图片有 alt、弹窗可键盘操作。
- 样式放 CSS；复用令牌；新增样式加作用域；品牌色变更需用户确认，不顺带改色。

## 4.3 SQL

- 表/字段小写下划线，避免保留字（`key`、`type` 在 MySQL 需反引号）。
- 保留 NOT NULL / UNIQUE / CHECK；业务校验帮助解释错误，数据库约束做最终兜底。
- SQL 参数必须绑定；动态表名/排序字段必须白名单；不清裸 `SELECT *` 直接透出接口。
- 筛选/排序/聚合/分页下推数据库；避免 N+1；索引依据实际查询计划。
- MySQL 方言改写顺序：**先 `key/type` 反引号，再 `ON CONFLICT → ON DUPLICATE KEY`**，否则会误改 `DUPLICATE KEY`。

## 4.4 事务、并发与幂等

- 库存预留、订单生成、流水、审计、通知按一致性边界提交；失败回滚；事务中不等待上传/人工/远端网络。
- 单件实物、防重复下单、重复回调必须同时考虑：事务内状态复核、原子更新、唯一约束、幂等键、冲突反馈。
- SQLite 的 `_WRITE` RLock 只解决单进程并发；**不能替代数据库事务、跨进程约束或生产并发验证**。
- 编辑/下架与下单竞争时，只接受当下有效状态与版本；草稿发布重复请求返回同一结果。
- 外部通知/支付等未来副作用与本地提交分离，采用可追踪、可补偿的执行记录。

## 4.5 迁移与原数据保护

- 只做有记录、可重复、先在副本验证的增量迁移；改数据前确认实际 `--data` / `HUALI_DATA_DIR` / `HC_DB`。
- **禁止清库、删除 `var-trial/`、用演示库覆盖试用库。**
- 字段改名/类型改动必须提供映射、旧值处理、客户端兼容测试；框架/目录/金额单位变更分别评估。
- D1 变更用 `wrangler d1 execute --remote --file=...`；schema 必须 `IF NOT EXISTS`，不得破坏性。

# 第五章 认证、权限与审计

## 5.1 密码与会话

- 注册/登录：手机号或邮箱 + 密码；密码 6—128；重复账号拒绝。
- **PBKDF2-HMAC-SHA256 600000 轮在浏览器端完成**；服务端只存 `salt`（32 hex）、`rounds`、`digest`（64 hex）。
- 恢复码 `secrets.token_urlsafe(32)`，服务端只存 `sha256` 摘要；只在注册/改密时展示一次。
- 会话 token 只存 `sha256(token)`；有效期 30 天；退出/改密/恢复后旧会话失效。
- 连续 5 次密码错误锁 15 分钟；认证接口限速；账号不存在也做等长比较，避免时序探测。
- 本地管理命令 `manage_trial.py reset-password` 只能由有服务器权限的人执行，必须指向与网站相同的数据目录。

**禁止：** 服务端接收明文密码做派生（Cloudflare 上 600k 轮会 CPU 超限）；降低轮数；把密码/恢复码/令牌写入日志或仓库。

## 5.2 RBAC 与分级清除

- 四级：`user(0) < support(1) < admin(2) < developer(3)`；普通注册只得到 `user`。
- 清除账号：`actor ∈ {admin, developer}` 且 `rank(actor) > rank(target)` 且 `actor != target`。
  - 开发者 → 管理员/客服/用户；管理员 → 客服/用户；同级/上级/自己不可清。
- 服务端必须逐次校验；不能信任前端隐藏按钮或请求体中的 role。
- 群主/群管理员权限仅限本群，不含客服/资金/全站信誉。

## 5.3 审计

以下操作**必须**写审计（操作人、对象、类型、理由、时间、关联实体）：

- 角色变更、停用/启用、重置密码、强制下线；
- 商品下架/恢复、内容处置；
- 退款建议/批准/执行、结算冲回；
- 信誉/星级调整、封禁/解封；
- 查看用户档案 `dossier_view`；
- **查看聊天正文 `chat_view`**（每次读取都写，reason 带会话号）；
- 清除账号 `account_purge`。

审计与对应状态同事务提交（本地 `tx()`；D1 `guarded_batch`）。

## 5.4 隐私与脱敏

- 手机号只在管理端脱敏显示（`138****1234` / `ab***@domain`）。
- 聊天正文不整包塞进档案；先列表+最后摘要，点开才读，读一次写一次审计。
- 管理端聊天弹窗明确标注“只读 / 档案对象 / 操作人 / 会话号”。
- 不记录明文密码、恢复码、Authorization、支付密钥、完整私密证据。
- 日志与备份限制访问；保留/清理策略按资料、交易争议、证据、备份分别制定。

## 5.5 密钥

- 不把 Token、OAuth 凭据、密码写进仓库/文档/聊天。
- Wrangler OAuth 凭据在本机受控目录；换机/换用户需重新登录。
- `.dev.vars` / 环境变量只放必要值；`.gitignore` 必须覆盖。

# 第六章 前端规范

## 6.1 状态、动作与路由

- 共享状态只在 `src/core/state.js`；其他模块只读写 `state`。
- 交互集中在 `actions/*`，由 `actions/index.js` 合并 `clicks`/`submits` 分发。
- `data-go` 负责导航，`data-action` 负责动作；**整行可点时，行内按钮优先**（`actions/index.js` 已有保护）。
- 页面不自己挂全局监听；需要时在 `registerActions()` 统一注册。
- 路由守卫：登录页、后台页、档案页分别校验；无权限时不渲染表单并给出明确提示。

## 6.2 页面与组件

- 页面函数返回 HTML 串，交给 `shell(content, active)` 包壳。
- 复用 `components/`（表单、商品卡、资料摘要、头像）；不复制一套相似 HTML。
- 页面必须有：加载、空内容、错误、重试、无权限；不能永久停在“正在打开”。
- 长表单保存要有防重复点击；失败保留输入；版本冲突提示“查看服务器资料并核对”。

## 6.3 设计令牌与设置页规范

| 令牌 | 值 |
| --- | --- |
| 品牌黄 | `#ffcc38` |
| 价格红 | `#ff4f33` |
| 画布 | `#f4f5f7` |
| 墨色 | `#2b2c30` |

**个人资料/账号设置页（2026-10-20 定稿）：**

- 白底、分组标题、细分割线、**不要 ①②③④ 编号**。
- 头像单独分组：预览左、操作右；上传/预览/取消/确认/移除顺序固定。
- 页脚只留“重新载入资料”，不要再放第二个保存按钮。
- 左侧设置导航只放**本页分区 + 账号与安全**；帖子/收藏/修改密码属于“我的”页，不重复。
- 分区用 `data-action="uc-scroll"` 平滑滚动；账号安全用 `uc-security` 弹窗。
- 移动端锚点 `scroll-margin-top` 要算上设置页自己的 sticky 标题行（header + 92，窄屏 + 140）。

## 6.4 错误与状态页

- 错误页按类型区分：权限不足、内容不存在、接口未开放（501）、服务异常。
- 非 JSON 响应不得直接 `JSON.parse`；先判 `Content-Type`。
- 网络失败不清除有效登录态；401 才代表会话失效。
- 加载失败提供重试；不要用“暂时无法打开”覆盖所有错误。

## 6.5 响应式与可访问性

- 至少检查 375 / 390 / 768 / 1440 宽度；无横向溢出。
- 弹窗按视口布局，不固定桌面像素；触控目标 ≥ 40px。
- 状态同时用文字和色彩；图标按钮有 `aria-label`；图片有 `alt`；键盘可操作。

## 6.6 禁止重复入口

新增入口前先查同类入口是否已存在；「我的」页与设置页、顶部导航与页面内导航不要互相复制。重复入口会让用户不知道哪个是准的，也会让后续改文案时漏改一处。

## 6.7 页面切换性能（2026-10-29 增补，硬约束）

**背景**：线上接口一次往返实测 0.7–3.0 秒（workers.dev 经代理访问），切页慢几乎全部来自“等网络”，不是渲染。任何人不得以“功能能用”为理由，让一次切页多等一个网络往返。

**必须**：

- 一次切页只允许**一次串行网络等待**：页面入口要有一个能直接渲染的数据请求，其余无依赖请求一律 `Promise.all` 并行。禁止“先取 A、再取 B、再取 C”的串行链。
- 页面入口接口必须登记在 `web 7M/src/core/http.js` 的 `CACHE_RULES` 并给出 TTL，否则二次进入仍要等完整往返。登记后由 `api()` 统一缓存、按账号隔离、任何 POST 自动失效；页面不得自建缓存副本或手工同步。
- 新增导航入口（`data-go`）必须在 `web 7M/src/main.js` 的 `PAGE_WARM` 登记预热数据；确实不能预热的（如需参数、轮询）要在提交说明里写明原因。
- 轮询接口（`/messages`、`/rooms`、`/badges`）禁止进入 `CACHE_RULES`，避免把聊天与未读状态缓存住。

**禁止**：

- 在首屏渲染前做与首屏无关的请求（角标、推荐、统计要么并行，要么渲染后再取）。
- 为省一次请求把两个语义不同的数据塞进一个接口，导致任一方变化都要整体失效。
- 用整页 `location.reload()` 代替局部刷新。

**验收**（每改前端必须实测并写进提交说明）：

- 同一会话内**二次进入**任一主页面（逛逛 / 社区 / 论坛 / 消息 / 我的 / 订单 / 客服）≤ 200 ms；首次进入只等一个网络往返。
- 命中缓存时该页面不应产生任何 `/api/*` 请求（浏览器 Network 面板可核对）。
- 提交说明附“改动前 → 改动后”的实测数字；没有数字视为未完成。

# 第八章 部署、备份与回滚

## 8.1 本地

```bash
# SQLite 试用（Windows）
start-trial-8081.bat
# 等价命令
cd "Backend mission"
python server.py --trial --port 8081 --lan
```

- 使用 `.venv-trial` 或系统 Python 3.8（需 PIL）；托管 3.13 无 PIL。
- `--lan` 绑定 0.0.0.0，同 WiFi 可访问；启动器会打印局域网地址。
- MySQL：`start-mysql-8081.bat` 或 `HC_DB=mysql://...`；切换前确认数据目录。
- 端口冲突：`netstat -ano | findstr :8081` → `taskkill /PID <PID> /F`；**不要同时起两个实例**（会出现两个进程抢端口）。

## 8.2 Cloudflare

- 配置：`Backend mission/wrangler.jsonc`（`main=worker.py`、`python_workers`、`assets.directory="../web 7M"`、`run_worker_first=["/api/*","/media/*"]`、`not_found_handling="single-page-application"`、D1/R2 绑定、cron）。
- 部署：
  ```bash
  cd "Backend mission"
  wrangler deploy --dry-run   # 先验证打包
  wrangler deploy             # 上传 Worker + Assets
  ```
- 记录 `Version ID`；前端资源与 Worker 必须同一次上传。
- D1 变更：`wrangler d1 execute zhuanjiao-trial-db --remote --file=app/cloudflare/schema.sql`（幂等）。
- 未注册接口返回 501；新增接口必须重新部署后验证。

## 8.3 干净 worktree 部署（并行改动时）

见 2.4。要点：从目标提交建 worktree、复制 `python_modules`、部署、删除 worktree；不把他人未提交改动带上线。

## 8.4 备份与恢复

- SQLite：`.backup` 生成一致性快照；连同 `uploads/` 图片；恢复到新目录验证账号/订单/图片。
- MySQL：`mysqldump`；恢复前停写；核对表数与关键行数。
- D1：定期导出（`wrangler d1 export`）；R2 记录对象清单；恢复后核对 30 表与图片引用。
- 备份含私人数据：不公开下载、不提交仓库、不放演示包。

## 8.5 回滚

- 先判断代码能否兼容现有 schema；已有新交易时，**不要直接恢复旧数据库丢弃增量**。
- 优先回滚 Worker 版本（Cloudflare 部署历史），保留 D1 数据；必要时暂停写入、备份现场、前向修复。
- 记录回滚原因、版本、数据影响与对账结果。

## 8.6 国内访问与合规

- `*.workers.dev` 国内被 DNS 污染（实测 `198.18.x.x`）；必须代理/VPN。
- 正式对外：自有域名 + 国内云服务器 + **ICP 备案**；或校园局域网先行。
- 二手交易属电商类目，评估 ICP 许可证与主体资质；不先收费。
- 真实用户数据建议迁回境内；跨境传输评估 PIPL 义务。
