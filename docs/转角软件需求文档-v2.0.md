## 1. 产品定位与目标

转角是面向校园的二手交易与交流平台，帮助学生、毕业生出售闲置物品，让有需求的同学以较低成本购买，并通过平台订单、交付记录和售后渠道减少交易纠纷。

首批从广州华立学院广州校区的**计算机工程学院**试点，先覆盖少量专业、真实卖家和真实求购需求。商品以**逐本二手书、宿舍日用品、运动闲置**为主，暂不以高价数码或奢侈品为核心。

产品希望完成三个基本结果：

1. 卖家能方便、如实地发布物品，买家能看清版本、缺陷、价格和交付方式。
2. 双方能在平台内沟通、出价、下单、约定交付，并在发生问题时留有可核查的记录。
3. 校园社区帮助同学交流、发布求购和认识其他卖家，但社区热度不作为交易信用担保。

### 1.1 已确定的经营约束

| 项目   | 要求                      | 当前状态                     |
| ---- | ----------------------- | ------------------------ |
| 运营者  | 个人试做，当前没有公司主体           | 未变                       |
| 试做预算 | 人民币 3,000 元；不得理解为已购买服务  | 未变                       |
| 首期地域 | 广州校区，优先计算机工程学院          | 未变                       |

| 首期登录 | 手机号/邮箱 + 密码；不发送短信，归属未验证 | 已实现                      |
| 交易   | 模拟支付、模拟退款、模拟结算，不收真实货款   | 已实现                      |
| 客服时间 | 每天 08:00—20:00，中国标准时间   | 已在界面标注                   |

### 1.2 试点成效

观察注册人数、真实有效商品数、求购响应、模拟下单完成率、取消原因、纠纷原因和客服处理时间。模拟成交量必须与未来真实成交量分开统计，不将测试数据当作平台业绩。

首轮建议邀请 10—30 名同学，完成至少 5 组买卖双方的完整试用，再决定是否扩大范围。这是试点建议，不是已完成的运营成果。

### 2.3 当前线上技术事实（供验收核对）

- **运行时**：Cloudflare Python Worker（Pyodide），不是普通 Linux 进程。
- **没有线程、没有真实 `sqlite3` 持久化、没有 `hashlib.pbkdf2_hmac`**；密码派生在**浏览器端**完成，服务端只存摘要。
- **D1 30 张表**；R2 存私有图片；静态资源由 Assets 直接出 CDN。
- **API 与静态资源同源**：`/api/*`、`/media/*` 进 Worker，其余走 Assets + SPA 回退。
- **未注册的 `/api/*` 返回 501**（“该接口尚未在试用版开放”），不是 404。
- **最新部署版本**由 `wrangler deployments list` 查询；本文不写死版本号，避免文档过期。

## 3. 版本范围与路线

### 3.1 V2.0：校园试用版（当前）

已经具备：账号、资料、发布、浏览、交易（模拟）、售后、社区、论坛、好友、客服、管理端、通知、双数据库、Cloudflare 线上部署。

V2.0 的验收目标不是“功能更多”，而是：

1. 20—30 名同学能独立完成“注册 → 发布 → 下单 → 交付 → 售后”闭环。
2. 客服/管理员能处理工单、内容、用户，且每一次敏感操作可追溯。
3. 线上与本地行为一致；数据可备份、可恢复；出问题能定位。
4. 文档如实反映“已实现/未实现”，不再出现“文档说有、页面没有”。

### 3.2 V2.1：国内可稳定访问 + 小范围正式试用

必须解决：

- **国内访问**：`workers.dev` 不可用；三条路径（按成本排序）：
  1. 自有域名绑定 Cloudflare（绕开域名污染，但仍走海外节点，稳定性有限）；
  2. 国内云服务器 + 已备案域名（推荐正式路线）；
  3. 校园局域网/校内服务器（当前阶段最稳，零备案）。
- **ICP 备案**：正式对外提供服务前完成；二手交易属电商类目，需评估是否需要 ICP 许可证而非仅备案。
- **数据合规**：真实手机号、聊天记录、订单数据迁回境内；隐私说明、注销/删除渠道、保留期限。
- **可选**：真实短信验证（提升账号归属可信度）、域名邮箱/微信登录。

### 3.3 V2.2：真实交易与小程序

在主体资格、支付方案、服务协议、隐私保护核实后：

- 接入合规的微信支付及退款/结算；平台不持有真实资金、不做可充值钱包。
- 微信小程序编译、真机测试、审核发布（需企业主体 + 电商类目资质，个人主体基本不可行）。
- 通知升级（订阅消息/短信/邮件分别授权）。

### 3.4 明确不做

首期不做自营回收、验机鉴定、充值钱包、贷款、高价奢侈品鉴定、跨校物流体系。校园互助不提供代考、代课签到等违反学术诚信的服务。

## 4. 用户角色与权限（V2.0 调整）

### 4.1 角色

| 角色      | 机器值         | 主要权限                           | 限制                   |
| ------- | ----------- | ------------------------------ | -------------------- |
| 游客      | —           | 浏览公开商品、公开帖子、公开主页               | 写入操作需登录              |
| 普通用户    | `user`      | 买卖、发布、下单、沟通、社区、工单              | 只能操作自己有权访问的数据        |
| 群主/群管理员 | 群内角色        | 处理所管群的违规消息、禁言                  | 不含退款、账务、全站信誉调整       |
| 客服      | `support`   | 工单受理/认领、商品下架、内容处置、用户档案（受限）     | 不审批退款、不调整信誉/星级、不授权人员 |

### 4.3 分级清除账号（2026-10-19 定稿）

- 开发者：可清除 **管理员 / 客服 / 普通用户**（不含其他开发者）。
- 管理员：可清除 **客服 / 普通用户**（不含管理员、开发者）。
- 任何人不能清除自己；不能清除同级或更高等级。
- 清除会移除登录信息与密码、强制下线、释放手机号给本人重新注册；历史订单/工单/评价/审计保留，昵称显示“已注销用户”。
- 自己的账号退出请走「我的 → 注销账号」，不是“清除”。

## 6. 账号、资料与隐私

### 6.1 注册与登录（已实现）

1. 手机号或邮箱 + 密码注册，昵称必填；注册时选择/确认学院、年级、专业。
2. 不要求身份证、学生证、学号、学校邮箱或人脸；不标注“实名/本校认证”。
3. 密码 6—128 字符；PBKDF2-HMAC-SHA256，**600000 轮在浏览器端完成**，服务端只存 `{salt, rounds, digest}`。
4. 登录会话 30 天；退出即失效；改密/找回后所有旧会话失效。
5. 连续 5 次密码错误锁定 15 分钟；认证接口另有频率限制。
6. 恢复码只在注册/改密时展示一次，服务端只存摘要；忘记密码且无恢复码时，由运营者核实后本地命令重置。
7. 账号不存在时也执行等长摘要比较，避免通过耗时差异探测账号。
8. 接口响应先判断 `Content-Type`；非 JSON 不得直接 `JSON.parse`，不得把 HTML 错误页当成业务错误。

### 6.2 个人资料（已实现）

- 字段：头像、昵称、学院、专业、学历层次、在读/毕业状态、个人简介。
- 学院由平台统一维护，用户不可自行改；学院是试点范围，不代表身份认证。
- 资料版本号 `profile_version`：多标签页/多设备编辑时，旧版本提交返回 409，前端提示“查看服务器资料并核对”，不静默覆盖。
- 头像：JPEG/PNG/WebP，原文件 ≤2 MiB，不支持动画；上传后先预览，确认才公开；可移除。
- 公开主页展示昵称、学院/专业、学历/状态、简介、信誉、在售商品；手机号不公开。

### 6.3 数据可见范围

| 数据               | 可见范围                   |
| ---------------- | ---------------------- |
| 商品标题、价格、商品图、公开介绍 | 公开浏览                   |
| 昵称、学院/专业、在售商品    | 公开主页                   |
| 手机号、恢复信息、私人凭证    | 不出现在公开页面和公开接口；管理端仅脱敏显示 |
| 私聊               | 相关双方；管理端**只读查看需逐次写审计** |
| 订单交付详情           | 交易双方及有业务需要的授权人员        |
| 售后证据/内部备注        | 相关用户按权限；内部备注不公开        |

### 6.4 注销与清除

| 操作   | 谁可以         | 结果                          | 手机号         |
| ---- | ----------- | --------------------------- | ----------- |
| 注销账号 | 用户自己        | 立即下线、在售商品下架、不能登录；订单/工单/信誉保留 | 继续占用，不能重新注册 |
| 清除账号 | 管理员/开发者（分级） | 匿名化、强制下线、历史保留               | 释放，本人可重新注册  |

> 有未完成订单或未结案工单时不能注销（防止“货不对版就注销跑路”）。清除是高危不可逆操作，必须填理由并写审计。

## 7. 商品发布与浏览

### 7.1 发布（已实现）

- 一页完成：选物品 → 填情况 → 拍照片 → 定价格和交付。
- 至少 3 张不同实拍图（正面/侧面/顶部）；相同文件不能重复凑数；最多 9 张。

- 交付方式：自提 / 校内送货 / 两者皆可；地点使用公共碰面点，不要求宿舍房号。
- 商品状态：草稿（未实现）、在售、交易锁定、已售、已下架、违规限制。
- 编辑在售商品不改变已生成订单的快照。

### 7.2 草稿与自动保存（未实现，V2.1）

V1.1 提出的“输入 2 秒自动保存、服务器草稿 + 本机补偿、草稿箱、30 天保留”**当前未实现**：

- V2.1 需补齐：草稿表、版本号、图片私有上传、跨设备恢复、冲突提示、保留期与隐私说明。

### 7.3 浏览、搜索与互动（已实现）

- 关键词、分类、学院/专业、课程、版本、成色、交付方式、价格筛选；最新/价格排序。
- 商品卡片显示图片、标题、售价、交付方式与对应费用；免费商品另收送货费也清楚显示。

## 8. 交易、订单与模拟账务

### 8.1 主流程（已实现，模拟）

浏览 → 私聊/出价（可跳过） → 确认商品与交付 → 创建订单并锁定商品 → 模拟付款 → 确认安排 → 实际交接 → 买家确认收货/满足自动收货 → 模拟结算 → 评价。

### 8.2 合并与费用（已实现）

- 同一卖家多件可合并下单，一次取货/送货；书仍逐本计价；不同卖家分开成单。
- 同卖家合并送货：取所选商品送货费中的**最高值，只收一次**；自提不收送货费。
- 平台服务费当前为 0；任何费用在下单前显示。

### 8.3 三种计时（已实现）

| 计时     | 当前规则                            |
| ------ | ------------------------------- |
| 待付款    | 创建后 30 分钟未付款，关闭并释放商品            |
| 确认交付安排 | 下单后 24 小时内确认；已付款未确认的超时取消并模拟退款   |
| 自动收货   | 买家确认实际交接后 24 小时，且无争议，才自动完成/模拟结算 |

**不得从付款时间或卖家单方“已送达”开始无条件放款。** 争议/售后暂停自动结算。

### 8.4 并发与幂等（已实现）

- 单件实物不能被两个买家同时锁定；并发下单只有一个成功。
- 重复点击、重复请求键返回同一结果，不重复生成订单/退款/结算。
- 支付、退款、结算、结算冲回分别记流水；金额整数分；所有记录标明“模拟”。

## 9. 售后与客服

### 9.1 工单（已实现）

类型：退款、举报、申诉、改约、咨询。状态：待处理、处理中、待补充、待协商/执行、已关闭、申诉中。

流程：选择订单/对象 → 选原因 → 填诉求 + 图文证据 → 双方协商 → 客服处理 → 退款等结果 → 关闭/申诉复核。

- 退款金额不得超过可退金额；支持全额/部分退款（模拟）。
- 退货退款需记录退回与验收；仅退款不恢复库存。
- 处理理由、时间线、内部备注、用户可见回复分别保存。

### 9.2 客服会话（已实现）

- 用户必须先提交工单，才能进入“在线客服”会话（防止免费咨询挤占客服池）。
- 客服会话**不挂在普通聊天列表**，走「我的客服 · 咨询进行中」入口；支持手动结束、30 分钟空闲超时、再发消息自动重开。
- 客服房豁免“先加好友才能聊天”的门禁；普通私聊仍受好友门禁。
- 客服回复写 `support_reply` 通知；客服可认领/释放会话，避免多客服撞车。
- 服务时间 08:00—20:00；非工作时间可提交工单，界面不得把“已入队”显示为“客服已读”。


### 9.3 退款后重新上架（部分实现）

- 未付款取消：释放商品回在售。
- 已付款未交付、取消并退款成功：核实物品仍在卖家处后释放。
- 退货退款：需卖家实际收到、退款完成、争议关闭，才可生成预填草稿/重新上架。
- 仅退款/部分退款且物品留在买家处：**不可**恢复出售。
- 平台下架/违规商品：卖家不能自行重新上架，需申诉复核。

> 当前实现：商品有 `relist_locked / lock_reason`，卖家不能绕过平台处置；退货重售的“预填草稿”尚未实现（与草稿功能一并列入 V2.1）。

## 11. 管理端与运营

### 11.1 客服工作台（已实现）

- 工单队列：按类型/状态/时间筛选，认领/转派，查看证据与历史，回复、内部备注、处理结果、提交复核。
- 商品：下架/恢复、待审商品复核。
- 内容：帖子/消息处置（移除/恢复）。
- 用户：查看状态与信誉，进入档案（仅管理员/开发者）。
- 资金：模拟对账，查看支付/退款/结算/冲回。
- 审计：只看自己经手或授权范围。

### 11.2 管理员工作台（已实现）

- 概览：待处理内容、运营账号、有货店铺、最近处置。
- 人员与权限：建号/改角色/停用/重置密码/强制下线；整行可点进用户档案。
- 店铺处置：整店下架。
- 敏感词库：内置 + 自定义，启用/停用。
- 审计：筛选、导出 CSV（带 BOM、公式注入防护）。

### 11.3 用户档案（已实现）

一屏聚合：基本信息、脱敏手机号、信誉分、在售商品、参与订单、工单、评论、帖子、评价、求购、处置记录、**会话列表 + 只读聊天**。

- 仅管理员/开发者可见；每次打开档案写 `dossier_view` 审计。
- 聊天正文**不整包塞进档案**：先给会话列表+最后一条摘要，点「查看会话」才读最近 200 条，且每次读取写 `chat_view` 审计。
- 聊天弹窗明确标注“档案对象”、只读、操作人/用户/会话编号。

### 11.4 信誉与星级（已实现）

- 信誉 100 分起；低于 60 不能发布新商品；已有订单仍可完成/退款/申诉。
- 星级 4—7 星：4 星起步；好评 3/8/20 条升 5/6/7 星；严重违规每次 -1 星、最多 -2；分数 <60/<40/<20 封顶 3/2/1 星。
- 管理员可 ±1/±2 调整星级，必须填理由，记入时间线；到边界时只记实际生效值。
- 举报/退款/差评本身不自动扣分；处罚需关联已核实工单、说明理由、可申诉、同事件不重复处罚。

### 11.5 内容审核（已实现）

- 内置敏感词 + 运营自定义词；命中可“拦截/待审/举报”。
- 帖子/评论/消息可处置；处置写审计、通知作者。
- 私聊正文默认不公开；管理端查看需审计。

## 12. 非功能需求

### 12.1 部署与运行

| 形态 | 要求 |
| --- | --- |
| 本地 Windows | `start-trial-8081.bat` 一键启动；使用 `.venv-trial`；`--lan` 允许同 WiFi 访问 |
| 本地 MySQL | `start-mysql-8081.bat`；`HC_DB=mysql://...`；连接必须 `autocommit=True` |
| Cloudflare | `wrangler deploy`；静态资源与 Worker **同一次上传**；D1/R2 绑定；`/api/*` 进 Worker |
| 定时任务 | `*/5 * * * *` 处理超时订单/自动收货；重复执行不得重复退款/结算 |

### 12.2 国内访问（关键新增）

- `*.workers.dev` 在国内被 DNS 污染（实测解析到 `198.18.x.x`），**必须代理/VPN 才能访问**。
- 免费版 Cloudflare 在中国大陆无节点；中国网络（China Network）仅 Enterprise + ICP 备案。
- 三条落地路径：自有域名绑 Cloudflare（改善但不保证）、国内云服务器+备案域名（推荐正式）、校园局域网（当前最稳）。
- 正式对外前必须完成 ICP 备案；二手交易属电商类目，需评估 ICP 许可证与主体资质。
- 真实用户数据（手机号、聊天、订单）建议迁回境内；跨境传输需评估 PIPL 义务。

### 12.3 性能与容量

- 首期按 30 名同时在线试用者验证浏览、消息、下单；不宣称支持全学院同时在线。
- Cloudflare Python Worker 冷启动明显（数百 ms 到数秒）；静态资源走 CDN，不绕 Worker。
- 列表筛选/排序/分页下推数据库；禁止全量读入 Python 再分页；避免 N+1。
- 上传图片限制大小/像素；去元数据；私有对象不公开直链。

### 12.4 安全

- 服务端逐次校验权限，不能只隐藏按钮。
- 密码 PBKDF2 600000 轮（浏览器端）；恢复码/会话只存摘要；不记录明文密码/令牌。
- 认证/发送消息限速；连续失败锁定；防暴力与刷屏。
- 防 XSS（动态文本转义）、SQL 注入（参数绑定）、越权（对象归属校验）、不安全上传。
- 公网 HTTPS；管理端敏感操作审计；审计与状态同事务提交。
- 密钥/令牌不写仓库、文档、聊天；Wrangler 凭据只在受控机器。

### 12.5 数据与备份

- 线上：D1 定期导出 + R2 图片清单；恢复需在新库验证账号/商品/订单/图片一致。
- 本地：SQLite 备份（`.backup`）含上传图片；MySQL 用 `mysqldump`；备份文件不公开。
- `var/`（演示）与 `var-trial/`（真实）严格隔离，禁止互相覆盖。
- 保留期：订单/售后/审计按争议需要保留；注销/清除后匿名化但保留历史；隐私说明需写明。

### 12.6 可观测与故障

- 页面区分加载/空/无权限/失败，失败可重试。
- 错误页按类型区分：权限不足、内容不存在、接口未开放、服务异常；不再一律“暂时无法打开”。
- 服务端错误不外泄堆栈；日志记录环境、错误类别、请求编号、去敏上下文。
- 部署记录版本 ID；前端与 Worker 必须同版本；出问题先回滚版本，不盲目恢复数据库。

| A11 | 收货与争议 | 卖家单方送达不放款；交接后计时；争议暂停结算 |
| A12 | 取消与退款 | 各状态入口正确；模拟退款与取消一致；不能既退款又结算 |
