# 个人资料 / 头像页改版方案（抖音设置页风格）

改造对象：`#profile/{id}`（自己的主页 = 资料编辑页 + 头像上传区）
参考：抖音「我 → 编辑资料 / 设置」的信息组织方式
范围：**只改界面与信息呈现，不动业务逻辑**（字段、校验、版本号并发、头像三态流程全部沿用现状）

现状问题：现在是两块 `.panel` 大圆角卡片 —— 资料表单是 `form-grid` 两列网格、头像区是居中大预览 + 一排等权按钮。字段和按钮平铺，缺少「分组」和「主次」，视觉重心落在卡片边框上而不是内容上。

## 二、对照现版本要改的 6 件事

| # | 现状 | 改为 | 理由 |
| --- | --- | --- | --- |
| 1 | 两块大圆角 `.panel` 卡片包住一切 | **去掉卡片外框**，改「白底 + 1px 分割线」分区 | 抖音设置页靠分割线组织，不靠卡片；去框后页面更整、更像工具 |
| 2 | `form-grid` 两列并排 | **一行一项**：左标签（132px）右控件（≤340px，右对齐） | 设置列表的扫读节奏是纵向的；两列并排会让人不知道该先填哪个 |
| 3 | 头像居中大头像 + 一排等权按钮 | **左预览（104px）右操作**，按钮分主次 | 头像的「预览」是结果、操作是手段，左右分栏比上下堆叠更直观 |
| 4 | 主按钮黄色 + 次按钮同尺寸同色 | 主按钮品牌黄 `#ffcc38` + 深字；次按钮**浅灰底/白底描边**；尺寸 36px | 现在「本地预览 / 取消 / 移除」和「上传并预览」长得一样，用户容易点错 |
| 5 | 保存按钮只在表单底部 | 标题行放一个主保存，底部保留一个 | 长表单里滚到一半想保存不用回到底部 |
| 6 | 学院是只读 input，和可编辑项长得一样 | 只读项**不用输入框**，直接一行灰字说明 | 输入框暗示「可以改」，点进去没反应会困惑 |

## 三、视觉规范

### 3.1 颜色

| 用途 | 值 | 说明 |
| --- | --- | --- |
| 页面底色 | `#ffffff` | 主区纯白；外层画布 `#fafafa` 只做区隔 |
| 主文字 | `#1a1a1a` | 昵称、标题 |
| 正文 / 标签 | `#3f3f46` | 输入内容、标签文字 |
| 辅助说明 | `#8a8a93` | 「展示在帖子和订单里」这类小字 |
| 弱化 / 占位 | `#b4b4bb` | placeholder、只读说明 |
| 分割线 | `#f0f0f2` | 1px，行与行之间 |
| 控件描边 | `#e6e6e9` | 输入框 / 下拉 / 选择框 |
| 主按钮 | 底 `#ffcc38`，字 `#2b2000` | 品牌黄 + 深字（对比度 10:1，不用发光也不用阴影） |
| 次按钮 | 白底 + `#e6e6e9` 描边，字 `#3f3f46` | |
| 聚焦 | 描边换 `#ffcc38`，不加外发光 | 只换边框颜色 |

**不用**：卡片阴影、渐变背景、彩色标签、大面积品牌色块。整页只有按钮是彩色的。

### 3.2 字号与行高

| 元素 | 字号 | 字重 | 行高 |
| --- | --- | --- | --- |
| 页面标题 | 20px | 700 | 1.4 |
| 分组标题 | 14px | 700 | 1.5 |
| 预览区昵称 | 19px | 700 | 1.4 |
| 标签（左侧） | 14px | 400 | 1.6 |
| 标签下的说明 | 11.5px | 400 | 1.5 |
| 控件内文字 | 14px | 400 | 1.6 |
| 辅助提示 | 12px | 400 | 1.7 |

### 3.3 尺寸

- 设置行最小高 **60px**，上下 padding 10px；行间用 1px 分割线，**不用间距**
- 标签列固定 **132px**，与控件之间留 24px
- 输入框 / 下拉：高 **38px**，圆角 **6px**，左右 padding 12px；最大宽 **340px**，右对齐
- 文本域：整行，高 ≥88px，圆角 6px
- 按钮：高 **36px**（主保存 38–40px），圆角 6px，左右 padding 16px
- 头像：预览 **104px** 圆形；资料预览区头像 **76px**
- 整页最大宽 **1080px** 居中，左右 24px

## 四、交互与状态（沿用现有逻辑，只改呈现）

1. **保存**：标题行与底部两个入口调用同一个提交，提交中两个按钮同时置灰（现有 `data-user-control` 锁定机制直接复用）。
2. **409 冲突**：仍在表单下方显示「资料已在其他页面更新」+「查看服务器资料并核对」，样式由红字改为**浅黄底提示条**（`#fff9e8` + `#7a5f00` 文字），与主按钮同色系，不引入新色。
3. **头像三态**：选择文件 → 本地预览 → 「上传并预览」→ 出现「确认设为头像」→ 确认后公开。三个阶段的按钮**显隐顺序不变**，只做视觉主次：
   - 未选文件：只有「选择文件」可用，「上传并预览」置灰
   - 已选未上传：「上传并预览」为主按钮
   - 已上传未确认：「确认设为头像」升为主按钮，「上传并预览」降为次按钮
4. **校验文案原样保留**：「支持 JPEG、PNG、WebP，原文件不超过 2 MiB；不支持动画与多帧图片。」——这行是上传前的唯一预期管理，**不要挪走、不要压成 11px 灰字**（现方案是 12px）。
5. **移除头像**：保持文字按钮（不是按钮框），点后弹 `confirm`，与现在一致。

## 五、响应式

| 断点 | 规则 |
| --- | --- |
| ≥1024px | 左标签 132px + 右控件，右对齐（如上图） |
| 768–1023px | 标签列缩到 108px；控件最大宽放开到 100% |
| <768px | **标签换到控件上方**（抖音 App 的样式），行 padding 12px 14px；输入框宽 100%、高 **44px**；按钮整行、高 44px |
| <420px | 预览区头像 60px，昵称 17px；底部操作条改为纵向堆叠 |

移动端还有一个必须处理的老问题：**保存按钮在长表单里够不到**——所以页面标题行做成 sticky（`position:sticky; top:0`），保存按钮常驻。

## 六、禁止项

1. 不做卡片阴影、不做渐变底、不做毛玻璃。
2. 不使用品牌黄以外的彩色（信誉标签是浅黄底，不算新色系）。
3. 不做「保存成功」弹窗——用行内提示条，2 秒淡出。
4. 不做头像拖拽上传、不做的裁剪框（现有功能里没有，这次也不加）。
5. 不改字段名、不改校验规则、不改版本号并发逻辑。

### 补充：文件选择改成自定义按钮（第一版遗留项的收口）

第一版为了「不动 `actions/user-profile.js`」保留了原生 `<input type="file">`，靠 `::file-selector-button` 改外观。
实际用起来有个硬伤：原生按钮的宽度和文案跟这一排按钮对不齐，视觉上很突兀。遂补成自定义：

- 结构：视觉隐藏的原生 input + `label.uc-file-btn`（点 label 等于点 input，键盘仍可 Tab 到 input 并用 `:focus-visible` 给 label 描边）+ `[data-user-file-name]` 回显文件名
- 事件层只加了两处：`showFileName()`（选完显示文件名、取消/确认后复位），以及把 `avatarFileChange` 的 id 匹配从 `#user-avatar-file` 放宽成 `#uc-avatar-file, #user-avatar-file`

**这里踩到一个真 bug**：改版把输入框 id 从 `user-avatar-file` 改成了 `uc-avatar-file`，而事件层还在按旧 id 匹配，
于是「选了文件没反应、不预览、不显示文件名」——但点「上传并预览」又能成功，因为提交时是直接读表单的。
只用肉眼过一遍代码发现不了，是 playwright 真跑了一遍「选文件 → 看文案是否变化」才暴露的。
现在两个 id 都认，避免未刷新的旧页面踩同一个坑。

### 另一处偏差

**学院行的说明文字改成左对齐**：右对齐时它像被截断的输入框，左对齐读起来是「一句话」。

## 附录：如果只做「头像上传」单独一页

若要把它从资料页里拆出来单独成页，结构如下（其余规范同上）：

```
站点导航（不变）
─────────────────────────────────────────────
① 我的头像                                    ← 页面标题
   上传后先预览，确认设为头像才会公开。

② 头像预览区（居中，大）
        ┌──────────┐
        │   头像    │  104px 圆形
        └──────────┘
     当前头像 · 2026-10-20 上传

③ 操作列表（设置行样式，每行一项）
   选择图片      [选择文件]  未选择任何文件
   上传          [上传并预览]         ← 主按钮
   确认           确认设为头像 ›（已上传后才出现）
   取消           取消本次选择 ›
   移除           移除当前头像 ›（文字按钮，确认后执行）
   提示           支持 JPEG、PNG、WebP，原文件不超过 2 MiB；不支持动画。

④ 底部 [ 保存 ]  ← 与资料页共用一个 profile_version
```

拆页的关键约束：**头像改动仍然递增同一个 `profile_version`**。如果拆成独立页而资料页还开着，保存时会 409——所以拆页的话，资料页要能自动重载版本，否则用户会莫名其妙被拒。
