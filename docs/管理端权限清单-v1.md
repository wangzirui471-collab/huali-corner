## 0. 先回应你的两条反馈

**「管理员权限太低」——成立，而且比你想的还低。**

全代码检索结果：现有管理端一共只有 10 项能力，其中**能"处置内容"的只有「群内禁言 / 删除群消息」一项**（`CommunityService.moderate`），
而且它还是给群主用的。**没有任何一个接口能下架别人的商品**——`CatalogService.set_product_status` 第一件事就是
`require(p['seller_id'] == u)`，管理员替卖家下架会直接 403。

所以你现在面对「卖家在商品里留微信号引流」这件事，手上是**空的**：既不能下架，也不能警告，连"标记一下回头再看"都做不到。

**「体验粗糙」——成立，我找到 6 个具体毛病**，见第 6 节，每条都附了代码位置。

## 3. 反引流专项设计（A1/A4/B5/B6 的落地方式）

### 3.1 检测什么

| 级别 | 命中内容 | 例子 |
|---|---|---|
| 高危 | 站外交易平台的链接 | 淘宝 / 闲鱼 / 拼多多 / 微店 / QQ 群邀请链接 |
| 高危 | 明确的加微话术 | 「加微信」「vx」「wxid」「加我好友」「扫码」 |
| 中危 | 疑似联系方式 | 11 位手机号、5–11 位纯数字（疑似 QQ） |
| 低危 | 交易外流话术 | 「私聊」「线下交易」「走微信支付」「绕过平台」 |

检测位置：商品标题、商品介绍、书籍字段（笔记/缺页/附件）、帖子、评论、聊天消息。

### 3.2 三级处置

| 级别 | 处置 |
|---|---|
| 高危 | **拦截发布** + 明确告知命中哪一条 |
| 中危 | **允许发布但打标**，进「风险待审」队列（A4），人工判 |
| 低危 | 仅记录，不打扰用户 |

### 3.3 两条必须说清的技术约束

1. **不能靠"见数字就拦"**：ISBN、价格、楼栋号（`L17`）、版本号全是数字，误伤率会很高。
   必须限定在"疑似联系方式"的上下文里（比如独立的 11 位号码、带 QQ/微信前缀的数字串）。
2. **图片里的二维码识别，v1 做不了**：`Backend mission/requirements.txt` 里**只有 Pillow**，
   二维码解码需要引入 `pyzbar` 或 `opencv`，与项目"标准库 + Pillow"的依赖策略冲突。
   → 建议 v1 靠**上传时文案提示 + 人工审**，不引入新依赖。

## 5. 防滥用五条铁律（每条新权限都受这五条约束）

1. **凡处置必写理由**，理由字符串进 `audit` 表。
2. **凡处置必通知当事人**，并给申诉入口——否则用户不知道自己为什么被下架。
3. **不得处置与自己相关的内容**：扩展现有 `check_conflict()`。
4. **默认不物理删除**：一律软删除/标记，保留可追溯。
5. **高风险动作二次确认**：下架整店、封禁、退款。

**另外有一条现有的坑必须一起修**：`check_conflict()` 对**平台自营商品**是**静默放行**的——
自营商品的 `seller_id` 是平台账号而不是管理员本人，所以 `seller_id != u` 永远成立，
管理员可以裁决自己平台引发的纠纷。这个坑在做「托管寄卖」时会真正爆掉，建议这次一并处理。

## 6. 管理端体验重做

### 6.1 现在粗糙在哪（6 条，附代码位置）

| # | 问题 | 位置 |
|---|---|---|
| 1 | 工单队列、用户表都是**全量平铺**，没有筛选、搜索、分页、排序 | `pages/support.js` 的 `staff` 函数 |
| 2 | **每点一次操作就整页重绘**，滚动位置丢失、页面闪烁 | `actions/support.js` 里到处 `await render()` |
| 3 | 封禁用**浏览器原生** `confirm()` + `prompt()`，样式不可控、填不了结构化理由 | `actions/support.js` 的 `ban` |
| 4 | 「信誉与管理权限」把**调整信誉**和**封禁**两类完全不同的操作混在一张用户表里，用户一多就没法用 | `pages/support.js` |
| 5 | 顶部导航「客服工作台」**没有高亮态** | `shell(..., 'staff')` 的 `'staff'` 不在 `desktop-navigation` 的导航项里 |
| 6 | 审计记录是 `<details>` 里一堆 `<p>`，不能按类型/操作人/时间筛 | `pages/support.js` 末尾 |

### 6.2 建议改成独立工作台布局

**左侧固定分区导航 + 右侧内容区**，7 个分区：

```
概览        待办卡片：我的待处理 / 待审商品 / 待处理举报 / 超时工单
工单        筛选（类型·状态·认领人·时间）+ 排序 + 批量认领 + 快捷回复模板
商品治理    搜索 + 按卖家聚合 + 风险标记 + 一键下架
用户        搜索 + 档案抽屉（订单/工单/违规/信誉/商品一屏）
社区        帖子评论队列 + 举报队列
资金        对账表格化 + 可按订单号查
审计        按操作人/类型/时间筛选
```

**交互原则**：

- 操作走**右侧抽屉**，不跳页、不整页重绘
- 所有写操作**局部刷新**，保持滚动位置
- 结构化表单替换 `prompt()`（理由用 textarea，不用输入框弹窗）
- 列表服务端筛选 + 分页，不再全量 `map`
