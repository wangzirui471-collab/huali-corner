## 1. 一句话说清这是什么

**校园二手交易平台的本地原型**，包含网站、微信小程序源码、客服后台与管理员后台。

三个必须先接受的前提：

- **不涉及真实资金。** 付款、退款、5% 服务费、置顶费全部是模拟记账，账本在 SQLite 里，没有接任何支付渠道。
- **手机号未验证。** 试用版用「手机号或邮箱 + 密码」登录，不发短信，不核验归属。
- **不是公开运营版本。** 没有实名/学号核验，没有内容安全兜底，没做压力测试。

## 2. 五分钟跑起来

前置：Windows + **Python 3.8 且装了 Pillow**。

> 不要用别的 Python。这台机器上装了多个版本，其中托管版 3.13 没有 Pillow，
> 一旦 `python` 解析到它，服务会报 `ModuleNotFoundError: No module named 'PIL'`
> 然后窗口一闪而过。启动脚本已经做了保护（见下），但自己敲命令时要留意。

```bat
:: 1. 双击（推荐）
start-trial-8081.bat        :: 端口 8081
start-trial.bat             :: 端口 8080

:: 2. 或手动
cd "Backend mission"
"C:\Users\Administrator\AppData\Local\Programs\Python\Python38\python.exe" server.py --trial --port 8081
```

然后浏览器打开 <http://127.0.0.1:8081>。

**关于启动脚本**：两个 bat 都会先试系统 3.8 的绝对路径 → 不存在再退回 PATH 里的
`python` → 用 `import PIL` 真跑一遍预检 → 失败时打印试过的解释器并停住窗口。
这样不会再出现「双击后窗口闪一下就没了」。

### 管理员账号

## 3. 账号与角色

| 角色 | 能做什么 | 入口 |
|---|---|---|
| `user` 普通用户 | 发布、下单、聊天、提工单 | 普通页面 |
| `support` 客服 | 工单全流程（含退款）、商品强制下架、商品复核、内容治理、用户档案（脱敏）、对账只读 | `#staff` 客服工作台 |
| `admin` 管理员 | 以上全部 **+** 恢复上架、信誉调整、封禁、人员与权限、整店下架、敏感词库、审计导出 | `#staff` 与 `#admin` |

**分权原则一句话：客服负责「做事」，管理员负责「担责」。**
判断标准是「这个操作会不会让平台自己成为需要被追责的一方」，会 → 归管理员。
详细矩阵见 `docs/管理员与客服分权方案.md`。

### 五条硬约束（改之前先看）

1. **页面不 import `router.js`，也不自己挂监听器。** 跳转一律 `data-go`，交互一律
   `data-action` + `actions/*.js`。否则会出现两个监听器抢同一个按钮。
2. **金额一律用「分」。** 前端只在展示时除以 100（`core/format.js` 的 `money()`）。
3. **改 Python 必须重启服务。** 前端改完刷新即可（必要时 Ctrl+F5）。
4. **词表不收单字。** 收了「刀」，「剪刀」「水果刀」「《刀锋》」全部误伤。代码层强制。
5. **审核命中词不对外公开。** 对外只给「是否在审」布尔值，公开了等于教人绕过。

## 5. 数据在哪、怎么备份

| 目录 | 内容 | 是否进 git |
|---|---|---|
| `var-trial/` | 试用版数据：账号、商品、订单、图片、词库覆盖、备份 | **否**（`.gitignore`） |
| `var/` | 本地演示版数据（seed 的虚构商品） | 否 |
| `var-trial/moderation/` | 运营在界面上改的词条（`custom.txt` / `disabled.txt`） | 否 |
| `Backend mission/app/moderation/data/` | **自建词表**（禁售品 + 反引流） | 是，要提交 |

- 自动备份：服务每 24 小时打一个 zip 到 `var-trial/backups/`，也保留服务端最近若干份。
- 手动备份：后台「客服工作台 → 资金」页底部，或 `POST /api/backup`。
- 恢复：停服务 → 解压 zip，把 `market.sqlite3` 与 `uploads/` 放进空数据目录 → 启动。

## 8. 内容审核怎么用

- 词库维护：管理员工作台 → **敏感词库**。新增 / 停用 / 启用，**保存即生效，不用重启**。
- 三种处置：`拦截`（直接拒绝发送）、`送审`（放行但进队列）、`仅记录`。
- 改动的词条写在 `var-trial/moderation/`，**不改仓库里的词表** ——
  否则每次拉代码都要冲突一次；停用列表也是独立文件，这样内置词条更新后不会复活。
- 开源词库（制爆、色情类）不随仓库提交，用 `scripts/fetch_wordlists.py` 按需拉取。
  仓库里只保留了许可证白名单，AGPL 与无许可证的仓库会被自动跳过。
- 待判内容在 **客服工作台 → 内容**。移除是软删除，判错了可以恢复。

## 10. 交接时要口头说清的三件事

1. **仓库是公开的。** 不要把口令、密钥、真实手机号、真实姓名提交进去。
   历史上的管理员默认口令就是这么泄露的，已经改成随机生成。
2. **这是模拟交易，不要真的收钱。** 页面上所有「支付」「退款」都不会动真钱。
3. **两个人不要同时改同一份工作区。** 动手前先 `git status`，
   改完立刻 `git add` 指定文件提交（不要 `git add -A`，容易把别人没写完的东西卷进去）。
