# 计算机工程学院可登录试用版

本版使用独立的手机号密码账号，可以发布三图商品、查看商品、收藏、私聊/群聊、合并下单和体验模拟售后。手机号不验证归属，不发送短信，不是实名或学籍认证。注册默认进入广州校区计算机工程学院；学院是试点范围，未证明访问者确为学院学生，获得链接的人均可注册。

所有订单、支付、退款和结算仍是模拟记录，不接微信支付，不真实收款或打款。建议先找一小组同学测试，再逐步扩大；没有做全学院同时在线的容量验证。

## Windows 先在自己电脑试用

1. 下载 `artifacts/huali-corner-trial.zip` 并解压到一个新的文件夹，不覆盖以前的数据。
2. 双击解压目录中的 `start-trial.bat`。
3. 保持终端开启，打开 `http://127.0.0.1:8080`，点「登录 / 注册」→「注册账号」。
4. 设置昵称和12至128字符的独立密码，阅读试用说明。注册后私下保存恢复码，不要发到群里。

若旧网站还占用8080，先在旧窗口按Ctrl+C停止。新电脑需安装Python（推荐3.12）并在项目目录执行 `python -m pip install -r requirements.txt`；此前已安装且能启动网站的电脑可以先直接启动。密码登录兼容改造不依赖新的第三方包。

命令行也可运行：

```powershell
python server.py --trial --port 8080
```

默认数据目录为 `var-trial/`，包括账号、商品、订单、图片与备份。旧演示版的 `var/` 保留，两个模式不能共用同一个数据库；程序会拒绝混用。重启后账号与数据保留，不用每次注册。

如果旧包在Windows上自动备份时报临时 `market.sqlite3` 的 `NotADirectoryError / WinError 267`，下载 `artifacts/huali-corner-windows-backup-fix.zip`。先按Ctrl+C停止服务，只用补丁内的 `market.py` 替换当前项目同名文件，再运行 `start-trial.bat`。不要删除或覆盖 `var-trial/`。修复明确关闭备份使用的SQLite连接后再清理临时目录，不需要重装Python或重建账号。新版完整试用ZIP也已包含该修复。

如果主页一直停留在「正在打开校园的另一个转角」，但 `/api/config` 能正常显示JSON，可使用合并修复包 `artifacts/huali-corner-windows-fix.zip`。它包含修复后的 `server.py`、`market.py` 和 `start-trial-8081.bat`，复制到项目目录替换程序文件，保留 `var/` 与 `var-trial/`。双击 `start-trial-8081.bat` 后访问 `http://127.0.0.1:8081`。该启动器明确使用密码试用模式，避免与8080上的旧演示进程混淆。

Windows的文件关联可能把JavaScript标为普通文本，浏览器在严格类型检查下会拒绝执行并停在初始加载提示。服务端已固定HTML/JS/CSS及图片类型，不需要修改Windows注册表、关闭浏览器检查或关闭安全响应头。如果检查配置，应在**8081**的 `/api/config` 看到 `"trial": true` 和 `"auth_mode": "password"`。目前仅复现并修复了这种类型映射导致的卡住，用户实际响应头仍需本机确认。

## 设置你自己的客服/管理员

本版不预设管理员手机号、默认密码或快捷客服登录。先在服务器或本机项目目录执行：

```powershell
python manage_trial.py create-admin
```

按提示输入你自己管理的手机号和密码，密码输入时不回显。请在邀请同学前先创建管理员。已注册的普通账号不能通过重复初始化自动变为管理员；管理员要使用独立管理号码。再次执行不会覆盖已有管理员的密码。

部署平台也可在首次启动前，通过其安全环境变量界面同时配置 `HUALI_ADMIN_PHONE` 和 `HUALI_ADMIN_PASSWORD`。初次创建成功后，账号保存在数据库中；重启不会用环境变量覆盖密码。不要把值提交GitHub、写进文档或发到聊天里。

普通注册接口只创建普通用户，不接受客户端传入的管理员角色。群管理员也没有资金与客服权限。已有工单、信誉调整与审核利益冲突检查继续生效。

## 密码修改与恢复

- 网页「我的」可修改密码；修改后所有设备退出登录，并生成新恢复码。
- 登录框「使用恢复码找回」需要手机号、对应的恢复码及新密码。找回成功后旧恢复码和所有登录会话失效。
- 没有短信验证，因此不能仅凭手机号重置密码。恢复码与密码一样需要私下保管，不提供给群友或陌生人。
- 如恢复码也丢失，需联系运营者，在另行核实账号归属后通过服务器本地命令 `python manage_trial.py reset-password` 处理。网页客服权限本身不能调用该命令。操作保留审计记录，并注销旧会话；输出的新恢复码需私下交给本人。
- 密码用独立随机盐和PBKDF2-HMAC-SHA256（600000轮）保存；数据库不保存明文密码。会话令牌、恢复码也只保存摘要。
- 连续5次密码错误后，该账号锁定15分钟；状态保存在数据库中，重启不会解除。高强度恢复码仍可用于恢复。HTTP认证请求另有限速。

## 发布到同学可以访问的网址

试用版必须运行Python后端并持久保存数据，不能上传到Netlify Drop的静态目录。此前的静态演示包只适合看效果。

仓库根目录的 `render.yaml` 提供了一个可选的Render部署配置。它使用 **Starter服务及1GB持久盘，属于付费资源**；本次没有代购、创建线上实例或承诺当前价格。开通前由账号所有者核对账单，不能把免费临时磁盘当作长期数据保存。

操作步骤：

1. 注册/登录Render，在其界面连接自己的GitHub私有仓库 `wangzirui471-collab/huali-corner`。只向平台授权所需仓库。
2. 选择从仓库Blueprint创建，读取 `render.yaml`，核对服务与磁盘费用后再确认。
3. 在平台安全输入界面设置自己的 `HUALI_ADMIN_PHONE`、`HUALI_ADMIN_PASSWORD`。使用独立管理号码和独立密码。
4. 配置指定Python3.12.12，安装 `requirements.txt`，启动 `python server.py --trial --host 0.0.0.0 --trust-proxy`；数据库与图片位于持久盘 `/var/data/huali`。
5. 程序读取平台注入的 `RENDER_EXTERNAL_URL` 作为HTTPS访问源。如果平台没有提供，需自己设置 `HUALI_PUBLIC_ORIGIN` 为实际HTTPS网址，例如 `https://实际域名`，不带路径。
6. 部署后先确认 `/api/health` 返回 `{"ok":true,"trial":true}`，再用两位普通用户测试注册、发布和订单。重启服务，确认账号与图片仍在，之后再分享实际网址。

`--trust-proxy` 只用于入口已由单个可信代理控制、后端无法被外部直接绕过的部署；它使用代理覆盖或追加在 `X-Forwarded-For` 链末的IP进行限速，忽略用户自行填写的前缀。自行部署或存在多层代理时，应在可信入口覆盖该头并核实最终客户端IP，后端端口只允许代理访问。不要直接开放Python端口，也不要给旧共享账号演示版配置公网绑定。

本次已验证本机真实HTTP请求、配置HTTPS来源的代理场景、账号隔离及浏览器流程。**未登录你的Render账号、未实际构建Render实例、未验证公网连通性，也没有生成可用公网网址。** 部署配置可供你核对，不等于已经上线。国内校园网络能否稳定访问所选托管服务，需实际测试。

## 数据与运行边界

- 只填写必要昵称、手机号和公共碰面点，不填写身份证、银行卡、微信支付密码或宿舍房号。手机号不会出现在公开主页。
- 实拍照片、商品介绍、社区帖子和公开主页会被其他访问者看到；聊天、订单和工单按权限读取。请勿在公开商品图中露出学生名单、证件或私人聊天。
- 客服工作台显示08:00—20:00，是运营安排；是否有真人值守由你安排。
- 自动任务每30秒处理超时，每24小时至少保存一次数据库和图片备份。备份本身包含私人数据、密码及令牌摘要，不能公开上传GitHub。需定期另存副本并演练恢复。
- 默认单实例SQLite，后台最多同时处理32个连接，请求读取有超时；没有多实例数据库同步与大规模压测。持久盘剩余空间和备份数量需监控，旧备份暂不自动删除。
- 对外试用期间，不进行真实付款，不声称平台已验证身份或能鉴别正版。短信验证、微信支付和正式生产运营仍需后续接入与验证。
