## 4. 本地启动与管理员账号

### 4.1 环境

- 推荐 Python 3.12。此次云端环境为 Python 3.12.14，依赖文件当前为 `Pillow==12.3.0`。
- 网页为原生 ES 模块，不需要先运行 npm 打包命令；Node 用于前端／小程序逻辑检查，本次环境为 Node v24.19.0。
- 浏览器自动化使用 Python Playwright＋Chromium，现有脚本主要使用 `/usr/bin/chromium`，Windows 需调整浏览器启动配置。
- 不因旧电脑的依赖安装失败而随意删除依赖或关闭 TLS 验证。

### 4.2 Windows 启动

打开项目根目录，即能看到 `start-trial-8081.bat`、`Backend mission` 和 `web 7M` 的目录。安装依赖后，可双击 `start-trial-8081.bat`；保持终端窗口运行。

PowerShell 逐行执行，路径仅为示例，按实际解压位置修改：

```powershell
cd "E:\projects\zhuanjiao-trial"
python --version
python -m pip install -r "Backend mission/requirements.txt"
python "Backend mission/server.py" --trial --port 8081
```

浏览器打开 `http://127.0.0.1:8081/#home`。不要双击 `index.html` 当作完整网站启动；不要把多个命令粘成一行。终端需要保留，停止时按 Ctrl+C。

Linux／macOS 采用相同目录结构，将命令中的 `python` 按环境替换为 `python3`。

### 4.3 使用旧账号和原数据

先停止旧实例，确认原数据目录并备份。完整新版解压到新目录后，显式指向原试用数据目录，例如：

```powershell
python "Backend mission/server.py" --trial --port 8081 --data "E:\原项目\var-trial"
```

上例路径必须替换为已确认的真实路径。第一次验证升级应优先使用原数据的副本，核对账号、订单、图片、工单和账务后，再用于原目录。

没有指定 `--data` 时，程序会使用 `HUALI_DATA_DIR` 或默认路径；因此，仅看文件夹名称不能证明正在使用哪个数据库。不要把演示模式的 `var/` 直接当作试用版账号库。

### 4.4 创建与恢复管理员

所有账号管理命令都应从项目根目录运行。新安装、使用默认试用数据目录时：

```powershell
python "Backend mission/manage_trial.py" create-admin
python "Backend mission/manage_trial.py" create-support
python "Backend mission/manage_trial.py" reset-password
```

按提示输入手机号及独立密码，密码 12—128 个字符。**如果网站使用了指定数据目录，上述命令也必须加相同的 `--data` 路径**，例如：

```powershell
python "Backend mission/manage_trial.py" reset-password --data "E:\原项目\var-trial"
```

- 没有交付默认管理员密码；交接文档不应填写真实密码或恢复码。
- 普通注册不能创建管理员；已有普通账号不会因重复初始化自动升级为管理员。
- 重复执行 `create-admin` 不覆盖已有管理员密码；忘记密码应使用恢复码或运营者本机的 `reset-password`。
- 运行重置命令前核实账号归属；重置会让该账号原会话和旧恢复码失效，生成的新恢复码要私下交给本人。
- 用户先前说过“管理员忘记密码，帮我注销账号”，但没有完成账号注销操作。不能把这句话当作已注销的记录，也不要擅自删除管理员账号。

## 5. 近期故障记录：8081 曾一直加载，用户反馈已恢复

### 5.1 已知事实与尚缺证据

| 类别 | 内容 |
| --- | --- |
| 用户已确认 | 当前访问 `http://127.0.0.1:8081/#home`。 |
| 截图现象 | 页面只有“正在打开校园的另一个转角…”，未出现完整首页或登录表单。 |
| 尚未确认 | 用户此次是否完整解压、实际运行哪份代码、实际数据目录、Python 版本、浏览器第一条报错、失败的资源或接口。 |
| 不能直接认定 | 密码错误、账号丢失、数据库损坏、必须重装 Python，或必须删除缓存／数据库。 |
| 本机访问边界 | 127.0.0.1 指访问者自己的电脑；开发者不能在另一台机器打开这个地址就看到用户现场。 |
| 目前状态 | 用户随后反馈“现在没有卡住了”。没有进行代码修复，根因仍未确认；没有重置用户密码或删除用户数据。 |

### 5.2 如果再次出现，按以下顺序排查

**第 1 步：确认 8081 上跑的是哪个实例。**

先查看原终端是否仍运行、有无报错，记录实际启动目录、启动命令和 Python 版本。Windows 可用：

```powershell
Get-NetTCPConnection -LocalPort 8081 -State Listen |
    Select-Object LocalAddress, LocalPort, OwningProcess
```

只停止确认属于旧版转角的实例，不要结束所有 Python 进程。确认后再启动完整新版，避免一直访问旧进程。

**第 2 步：在用户同一台电脑检查接口。**

```powershell
Invoke-RestMethod "http://127.0.0.1:8081/api/health"
Invoke-RestMethod "http://127.0.0.1:8081/api/config" |
    Select-Object name, trial, auth_mode, phone_verified
```

试用版期望 `/api/health` 包含 `ok: true`、`trial: true`，配置包含 `auth_mode: password`、`phone_verified: false`。这只能证明对应接口可用，不能证明整个网页或登录流程已正常。

**第 3 步：检查前端入口及第一条浏览器错误。**

在浏览器按 F12，查看 Console 和 Network，刷新一次，记录第一条红色错误及第一个失败请求的路径、状态码和响应类型。重点包括：

- `/src/main.js`、其 import 引用的模块和新增 `staff.css` 是否来自同一版、是否存在。
- JavaScript 请求是否返回 404、HTML 错误页或错误 MIME 类型。
- `/api/config`、已有会话的 `/api/me`、首屏商品查询是否卡住或失败。
- 是否存在语法错误、模块导出不匹配、跨源或浏览器存储访问错误。

仅凭一个模块返回 200 不能排除其依赖加载失败。分享报错时不要发送密码、Authorization 头、会话令牌、恢复码或未脱敏的完整 HAR 文件。

**第 4 步：核对完整包，并做不影响原账号的对照。**

确认是功能分支／对应完整包；先用 Ctrl+F5 强制刷新，可以临时禁用浏览器缓存再观察。不要先清空全部站点数据，避免误删尚未同步的本地草稿。

如需要区分旧进程／旧文件与当前代码，可将完整源码解压到新目录，使用独立端口和独立诊断数据：

```powershell
python "Backend mission/server.py" --trial --port 8082 --data ".\var-diagnostic"
```

打开 `http://127.0.0.1:8082/#home`。诊断目录没有旧账号属于正常现象；它只用于检查启动，不能覆盖原 `var-trial/`。

**第 5 步：查到原因后再修复和验收。**

静态 import 失败会发生在 `main.js` 的 try/catch 运行之前；当前请求层也没有统一的浏览器请求超时。这是源码中可见的排查线索，**尚未证明就是用户这次故障的原因**。不能仅加提示、改密码就宣称已修复。

修复应覆盖“从启动 → 首页 → 打开登录框 → 用正确账号登录 → 重新加载仍能恢复会话”。还应验证错误密码有明确提示、账号原数据仍在。先记录根因和回归结果，再关闭故障。

## 7. 已实现能力与重要业务规则

### 7.1 商品、草稿与订单

- 二手书及生活、运动、电子产品闲置，支持查询、收藏、点赞、分享和出价。
- 发布采用三步表单；至少三张不同实拍图，指定正面、侧面、顶部。照片不代表自动鉴定正版或保证不是网图。
- 书逐本展示、独立定价；版次、笔记、缺页、附件可选择“待核对”，已知问题需披露。4 元是可选定价提示，不是当前强制最低价，允许免费转让。
- 草稿服务端保存、版本冲突检测、恢复和重复发布防重；临时缓存按账号隔离。切换账号、晚返回上传不能覆盖新账号或新页面。
- 同一卖家多件可合并下单、合并取货，送货费按所选物品的最高送货费收取一次；不做跨卖家资金合并。
- 金额存储与原接口合同使用整数分；界面元字符串通过统一校验入口转换，禁止直接依赖浮点数截断。
- 待付款订单可按权限修改／取消；已有订单保留商品、价格、地点和时间快照，后改商品不重写原订单。
- 下单后 24 小时确认安排与收货倒计时不同。当前自动收货从买家核对交接后计 24 小时，争议中暂停；卖家单方“已交付”不是自动结算起点。

### 7.2 售后、信誉与重新上架

- 售后工单支持证据、回复、内部备注、认领、转派、建议和管理员模拟退款。
- 仅退款不会自动恢复在售库存。退货重售需要实物退回、卖家确认、退款完成、争议关闭，再生成重售草稿。
- 信誉初始 100，低于 60 暂停新发布；举报、差评、退款不会自动扣分。管理员须关联已核实工单、按规则处理，保留理由与申诉记录。
- 下架商品、退款和信誉处罚是不同动作，不能互相代替，也不能因为一张截图直接修改账务。
- 工作人员不能处理与本人有利益冲突的工单及信誉处罚。

### 7.3 最新工作台与直接下架

这一批功能是 `b2fd4d2` 的增量，早期 V1.4 需求文档的一些“待补”描述已落后，应结合 `docs/STAFF_WORKSPACE.md` 阅读。

| 内容 | 当前行为 |
| --- | --- |
| 商品直接下架 | 商品详情“举报商品”旁有红色“下架商品”，仅管理员／客服可见，服务端再次鉴权。 |
| 下架效果 | 必填原因；停止公开展示和新下单，报价失效，通知卖家，有商品关联审计，不自动扣分。 |
| 下架限制 | 仅在售商品可直接处理；交易中的商品先处理订单。`staff_delist` 不能由卖家自行恢复。管理员违规商品恢复审批流程尚未新增。 |
| 管理入口 | 手机和电脑“我的 → 进入管理工作台”；独立分区导航。 |
| 待办 | 待认领、我负责、待复核、有新通知、超过 24 小时未更新；筛选、分页、负责人昵称、更新时间。 |
| 未读与超时 | “新通知”来自消息中心未读，不是逐工单正文已读；24 小时按实际经过时间，不是客服工作时长。 |
| 关联原内容 | 新举报保存商品／帖子快照，详情可查看；旧工单无快照时标为当前内容。 |
| 退款／扣分 | 显示相关金额或预计信誉变化，提交前确认；取消确认不执行。最终资格由服务端核验。 |
| 客服停用 | 撤销会话，将未结工单退回待分配队列，保留待复核状态，记录交接并通知。 |
| 审计与备份 | 审计可搜索、分页和跳转关联对象；展示最近备份创建状态、异常及恢复说明。 |

### 7.4 社区和消息

支持帖子、私聊、主动加入总群／学院群。学院群满 500 人分流，不在注册时自动拉群。群角色仅有群内职责，不等于客服或平台管理员。

校园互助首版是信息发布＋私聊协商＋反馈举报，没有服务订单、服务支付或真实佣金。代考、代课签到等违反学术诚信的服务不纳入已确认首版。

订单、售后、私聊及商品下架有站内通知。浏览器提醒依赖网页运行及浏览器支持，不能承诺关窗或手机后台仍收到；微信订阅消息尚未接入。

## 9. 数据、备份与不能破坏的约束

### 9.1 真实数据与源码分开交接

- 本次源码包不携带任何真实账号库。朋友首先应使用新建测试账号和合成数据排障。
- 如果确需接触用户原数据，另行核实授权和最小必要范围；不要把整份数据库、工单证据、备份或学生表直接提交 GitHub。
- 原补考表只用于提取去重组织目录，不能导入或展示姓名、学号、成绩等学生数据；提取目录也不能证明学校最新完整组织关系。
- 不在代码、文档、日志或群聊填写真实密码、恢复码、令牌、支付密钥。

### 9.2 升级与恢复

试用数据包含 `market.sqlite3`、`uploads/`、`backups/`。备份要保存数据库与其对应图片的一致性快照，不能只复制网页源码。

已有后台备份与命令行后台任务；备份创建成功不等于已完成目标机恢复演练。建议更新前停止服务，将整个实际数据目录另存一份，先在副本中验证增量迁移。

恢复时先停止服务，解压备份到新的空数据目录，再使用 `--data` 指向该目录，检查账号、订单、照片、工单和对账。不得直接覆盖原目录或把新空数据库覆盖旧账号库。

如果更新后已产生新订单，不能直接回滚数据库而丢弃新增交易。先暂停写入，保留故障现场与最新数据，再评估兼容的代码回滚或迁移修复。

### 9.3 开发硬约束

1. 路径只由 `app/core/config.py` 推导，不在各模块重复拼项目根目录。
2. 保留 SQLite DELETE 日志模式和既有事务组织；数据库非空、唯一和校验约束不能因为模板规定而撤掉。
3. 进程内写锁不是跨进程锁，也不能单独证明不会超卖。并发测试要用不同用户／不同请求键。
4. 不清库解决兼容问题，迁移增量、可重复，验证旧数据。
5. 网页共享可变状态放 `src/core/state.js`；页面不能反向 import router 形成循环。
6. 业务按领域放目录，页面负责渲染，动作进入 actions，复用片段进入 components；不恢复巨型 app.js／market.py。
7. 禁止全局正则改标识符导致 API 路径、模板字面量和静态资源被误改。
8. 不强推、覆盖 `main` 或修改无关项目；当前功能分支的测试通过不代表已合并主分支。

- 补充转角特有的草稿与账号隔离、订单幂等、实物库存链、客服分权、证据隐私、模拟资金和 AI 辅助开发要求。
