# main 版本：商品详情与首页管理下架修复

日期：2026-10-17（北京时间）。入口修复基线：main 的 c44b478；本次在38e3f66上按用户最新要求修订权限，并保留另一开发者b807101的个人页/样式及d29cc01的消息/订单/角标更新。保留当前 Logo、华立转角名称、独立客服/管理员工作台及最新个人页面。

## 原因

用户截图顶部有客服、管理员两个工作台；这与 main 的 `core/shell.js` 一致，管理员工作台由 `state.me.role === 'admin'` 控制，不能仅凭“我的”页面没有相同入口就认定普通账号。

main 原先已注册 `actions/staff.js` 的 `moderate-product` 动作，后端也有 `/api/product/moderate`，但商品详情与首页卡片没有渲染该按钮。另一个分支的修复使用 `/api/product/moderation`，不能直接把那一分支的入口和后台覆盖到 main。

## 修复范围

- 新增纯组件 `web 7M/src/components/product-moderation.js`。
- 下架按钮样式独立在同目录 `product-moderation.css`，由 `index.html` 加载；不把样式附在另一开发者正在修改的个人页面样式尾部。
- 商品详情“举报商品”旁显示红色“下架商品”；首页商品卡片底部也显示。
- 管理员：所有卖家的在售商品均显示管理下架，包括本人商品；填写理由并记录审计。
- 普通用户：本人在售商品显示自主下架，他人商品不显示；服务端校验商品所有者，伪造请求也不能越权。
- 客服：他人商品继续按原职责管理下架；本人商品使用卖家自主下架。
- 复用已注册 staff 动作及 `/api/product/moderate`，自主下架复用 `delist` 动作及 `/api/product/status`；不新增平行接口，不改账号角色、数据库结构、Logo、工作台或用户中心页面。
- 只对在售商品提供下架；已预留、交易中和已售出商品仍须走订单/售后流程。写事务内再次检查最新商品状态，避免读到在售后被另一订单预留却仍覆盖成已下架。
- 原后端的下架、审计、卖家通知与禁止卖家自行恢复规则继续生效。取消弹窗不下架；确认后刷新当前页。

## 如何更新

这次修复提交到 main，不需要切到之前的 `feat/layered-completion` 版本。

Git 克隆用户：在实际运行的项目目录停止服务后，确认没有未保存修改，再拉取 main；有本地改动先保存提交，不强制重置。重新运行原启动方式。

ZIP 用户：

1. 停止旧服务，备份当前实际试用数据目录（通常为项目根的 `var-trial/`）。
2. 将 main 修复版完整解压到新目录。不要只换 server.py，也不要直接拿空数据目录覆盖原库。
3. 将原数据目录的完整副本用于新版，或用原启动命令的 `--data` 指回同一目录；账号、照片、订单与备份要一起保留。
4. 若使用默认 `var-trial/`，将完整副本放在新版项目根，再双击 `start-trial-8081.bat`。自定义数据路径继续沿用原路径设置。
5. 保持终端运行，使用原管理员/客服账号登录，在商品详情按 Ctrl+F5。正常位置是“想要·私聊 / 我来出价 / 举报商品 / 下架商品”。

本次没有修改密码、升级普通账号、创建真实管理账号或清空数据，也没有部署到用户电脑；本机更新仍需由操作者执行。
