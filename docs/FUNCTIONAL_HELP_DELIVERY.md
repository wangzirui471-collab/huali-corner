# 功能缺陷修复与校园互助交付

本轮在现有分层功能分支完成，不覆盖main。依据用户确认，校园互助首版仅“发布需求＋私聊协商”，不接真实支付或抢单结算。

## 修复内容

1. 客服未认领只能看工单摘要，不能读无关订单地址、内部文字或证据；转派撤销旧客服访问，全站审计/对账/备份限管理员。
2. 卖家待付款改单只呈现并提交允许的时间字段；买家的字段校验保留。
3. 网页/小程序卖家可取消待付款订单，通知发给另一方，文案区分买家和卖家。
4. 未交付订单不要求退回实物，新错选归一化、历史错选也可受控退款，不伪造实物退回记录或借此重售。
5. 结案工单只读，新材料通过关联申诉进入新队列；原工单、依据和退款不改写，不假成功认领。
6. 私聊新消息进入通知与会话未读；已读游标持久化，只覆盖已加载范围，消息重试不重复通知。
7. 私聊按当前用户显示对方名称；小程序切群清理旧消息和游标。
8. 退出清理当前账号本机创建/编辑草稿与清单，保留服务器草稿。网页退出单次执行并绑定原会话，延迟响应不清除新账号。

## 校园互助怎么使用

网页：社区→“逛逛互助／发布需求”；小程序：社区→校园互助。

- 支持需要帮助/提供服务，快递代取、资料代交、搬运、学习辅导/笔记及其他互助。
- 填标题、意向报酬（可面议或0元）、公共地点、截止时间、说明；无商品三图要求。
- 可按类别/方向/状态搜索，查看自己的发布；作者关闭/再次开放，过期不继续招募。
- 联系发布者进入私聊，不创建服务订单、不收取真实服务费、不承诺履约担保。取件码等不设为公开字段，应在私聊提供。
- 举报/反馈关联原帖进入客服；工作人员不能审核自己的帖子，核实处罚沿原规则执行。
- 结构化互助只在专门列表呈现，避免关闭/过期后仍以普通社区帖继续招募。

“代课”具体含义尚未补充，首版沿既有需求不设置替人签到/代考类别；课程辅导和笔记整理已有。

## 启动与升级

下载完整源码包，解压后用Python 3.12安装 `Backend mission/requirements.txt`，双击start-trial.bat，或从项目根运行：

```bash
python "Backend mission/server.py" --trial --port 8080
```

浏览器打开本机8080端口，保持终端运行。旧数据先停服备份，在副本上用完整新版验证升级；数据迁移只增表/列，不删除账号、订单、图片或账务。不要只替换server.py，也不要把演示库混作试用账号库。
