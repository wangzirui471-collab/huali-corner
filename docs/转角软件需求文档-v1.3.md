## 1. 产品定位与目标

转角帮助学生和毕业生出售闲置物品，让同校有需求的人低成本购买。首批在广州华立学院广州校区的计算机工程学院试点，先覆盖少量专业；优先逐本二手书、宿舍日用品和运动闲置，保留已有电子产品频道，暂不把高价数码和奢侈品当作主要市场。

核心目标：卖家容易发布且如实披露；买家看清版本、缺陷、价格和交付；订单、协商与售后有记录；社区帮助交流和求购。点赞、收藏及群内热度不作为质量或信用担保。

### 1.1 已确定的约束

| 项目 | 要求 |
| --- | --- |
| 运营主体与预算 | 个人试做、暂无公司；总预算3,000元，仅为支出上限建议，未购买服务。 |
| 首期人群 | 计算机工程学院试点；不要求学生证明，毕业生可注册出售。 |
| 登录 | 手机号＋密码，不发短信；未验证的号码不能当作身份认证或找回密码依据。 |
| 学校范围 | 先广州校区，本科和专科为主要人群；中专暂不开放独立市场与社区。 |
| 交易资金 | 全部模拟支付、退款、结算；暂不真实收费，不建立真实资金余额池。 |
| 客服时间 | 每天08:00—20:00，中国标准时间；非服务时段仍可提交，需提示待处理。 |
| 品牌 | 对外名称“转角”；ZJ辅助标识，最终Logo与颜色另定。 |

### 1.2 试点成效

建议首轮邀请10—30名同学，至少完成5组买卖双方的完整试用，记录有效发布、求购响应、完成率、取消原因、纠纷及客服耗时。该目标尚非运营成果；模拟订单、测试数据与未来真实成交必须分别统计。

## 3. 角色与权限

| 角色 | 可做什么 | 边界 |
| --- | --- | --- |
| 游客 | 浏览公开商品、帖子和主页 | 写入、聊天、下单需登录。 |
| 普通用户 | 同一账号买卖、发帖、聊天、工单和申诉 | 仅访问自己有权看的订单、草稿、证据和私人资料。 |
| 群管理员 | 在授权群删除违规消息、禁言等 | 无退款、账务或平台信誉权限；完整群主层级和成员管理界面待补。 |
| 群主 | 目标为承担群管理和协调职责 | 不能任意授予平台权限；当前未形成独立完整角色闭环。 |
| 客服 | 独立账号、认领/转派、回复、取证和退款建议 | 不批准资金、不任意加减分、不处理自身交易；证据访问受工单权限限制。 |
| 平台管理员 | 建立/启停客服、退款审批、规则处罚、申诉、账务和备份 | 敏感操作留痕；参与自身交易时避嫌，不能绕过服务端限制。 |

普通注册只能获得普通权限。群管理可通过申请、推荐后由平台审核授权；前端隐藏按钮不能替代服务端鉴权。校验分布在相应领域服务及HTTP入口，执行状态变更时还要在写事务内复核账号和交易资格。

### 4.2 管理工作台

当前已有工单类型/状态筛选、待处理统计、认领转派、人员建号启停、证据、回复、退款建议/审批、规则信誉、对账与备份相关入口。待补逐工单未读、新材料提醒、超时排序、停用人员未结工单交接、完整目录维护及统计。不能将全部目标一并标为完成。

### 4.3 视觉和异常体验

借鉴闲鱼、转转的搜索、分类、双列卡片和突出发布入口，形成转角自己的设计。图片和价格优先，宣传区不能把首批商品挤出手机首屏。375、390、768、1440宽度为已有浏览器检查档位，设备实测仍需补。

加载、空内容、失败重试、权限不足、表单保存中和冲突应有明确状态。不能把网络失败显示成没有商品，也不能永久停在“正在打开”。已覆盖主要流程，所有异常组合仍需持续验收。

### 4.4 品牌与样式基线

当前网页主题仍为品牌黄#ffcc38、价格红#ff4f33、画布#f4f5f7、墨色#2b2c30。样式以网页market.css及小程序app.wxss为依据，避免各页自行发明一套。最终白绿配色尚未定稿，不能写成已替换。

Logo应让人第一眼理解“二手交易”，可结合交换箭头、物品、标签，并配“校园二手交易”；ZJ为辅助，不能只凭抽象字母验收。旧五分区发布及右侧实时预览属于历史设计，当前三步发布没有该实时预览，后续如恢复需单独排期。

## 5. 账号、个人资料与隐私

### 5.1 登录与安全

手机号＋密码注册登录，密码12—128字符；手机号不公开，不发送验证码，也不代表号码所有权已认证。连续5次错误后按15分钟锁定策略处理。密码以加盐派生结果保存，不保存明文。提供一次性展示的恢复凭据；改密和恢复后撤销旧会话。不得把客服共享密码写入文档或源码。

### 5.2 资料与注册简化

基础字段：昵称、学院、专业、教育信息、自我介绍；学校与专业目录应支持“其他/待确认”，缺少学籍材料不阻止注册。当前教育字段包含本科、专科、已毕业、其他，尚未把“学历层次”和“在读/毕业状态”独立建模；不得声称此拆分已完成。

当前公共头像为文字/首字头像，自定义头像上传未完成。学院专业自填信息只帮助检索，不作为认证徽章。毕业生仍可出售商品，后续不得因毕业清空订单或禁用售后。

### 5.3 可见性与数据权利

| 数据 | 可见性与处理要求 | 现状 |
| --- | --- | --- |
| 公开资料、商品和社区内容 | 公开字段与私密字段分开；手机号不附带在公开用户DTO中 | 基础隔离已有。 |
| 手机号、密码、恢复凭据 | 不向其他用户公开；凭据不可写入日志/备份说明/交付包 | 已有核心保护，持续审计。 |
| 精确地址与订单证据 | 仅当事人和有权限人员可看；公开商品只写公共交接点 | 基础权限已有，目录/提示需完善。 |
| 发布草稿和编辑缓存 | 服务端按账号隔离；本机明确缓存范围，退出应清理可读副本 | 服务端隔离已有；网页退出清除创建草稿本机缓存尚不完整。 |
| 注销/删除/导出与保留 | 提供申请渠道，按资料、交易争议、证据、备份分别说明保留 | 专门入口与统一政策待补。 |

不能承诺注销立即删除全部交易与争议记录。未核实举报不能自动封号或让用户失去售后权利。真实数据收集范围扩大前，应完善告知、删除申请、保存期限和访问审计。

## 6. 学校、学院、专业及地址

### 6.1 目录范围

试点配置以计算机工程学院为主，后续目录按“学校/办学单位→校区→学历层次→学院→专业”维护。原补考表只能提取学院/专业候选，不导入学生身份、成绩或联系电话；表中名称可能为历史名，不自动当作现行招生目录。

本科与专科可能涉及不同办学单位，不能只凭同校区就称为一个学校。扩展前需记录官方来源、核实日期、别名和关系；中专市场暂不开放。当前未完成全广州校区学校数量及官方目录核实，也没有完整管理员维护界面。

## 10. 售后、客服、退款与退货重售

### 10.1 售后原则与入口

二手交易以如实描述和双方约定为基础，平台不承诺无条件包赔、鉴定或先行赔付。不喜欢优先协商，描述不符、缺陷隐瞒、未收到货等由客服核对证据与责任，按规则处理退款或退货。

买家在订单发起售后/退款，选择原因、说明、证据；卖家可回复。商品、用户及社区内容可举报，通用反馈与申诉进入相应工单。平台外成交缺少平台订单和支付记录，不能走该订单售后；涉及平台内容和违法违规仍保留举报渠道。

### 10.2 工单、证据与冲突回避

### 10.3 退款分工与三级记录缺口

客服可提出退款建议、理由和金额，管理员批准或拒绝；普通客服不能直接改账。当前模拟退款批准与执行仍在同一流程落账，支持现有金额约束，但没有独立的“待执行/执行中/成功/失败/重试”执行记录层。

重售不是把原订单改成未成交。原订单、照片/价格/书况快照、退货记录和退款账保留；预填草稿需卖家核对当前实物、重新确认缺陷与照片后发布。合并订单逐件重售须在逐件售后落地后继续完善。

### 10.7 申诉

用户可就处罚或处理结果提交申诉并补证；受控冲回要求关联已解决申诉、校验原处罚、避免重复冲回。已有服务端能力，界面仍需完善原处罚选择、明确“成立/不成立/待补证”结论和提醒，不能用通用结案代替全部申诉结论。

## 12. 信誉积分、处罚与申诉恢复

### 12.1 已启用的规则计分

初始100分，范围0—100；低于60分不能发布、恢复/重新上架，60分边界允许。已有订单、售后与申诉入口继续保留。举报本身不扣分，须核实相关工单后，由有权限且无利益冲突的管理员执行规则，程序计算并留审计。

| 规则代码 | 已核实事实 | 规则后果 |
| --- | --- | --- |
| minor_issue | 轻微问题 | 提醒，0分。 |
| no_show | 爽约 | 首次提醒；30天内独立重复事件扣5分，禁止同一事实重复叠加。 |
| description_omission | 描述遗漏 | 扣5分。 |
| hidden_defect | 隐瞒缺陷 | 扣15分。 |
| outside_surcharge | 订单外要求补款 | 扣10分。 |
| forged_evidence | 伪造证据 | 扣20分。 |
| fraud | 欺诈 | 扣50分并限制交易、移除可售商品；不靠自然时间解除。 |

记录原分、实际扣分、后分、依据、工单和操作者；分数已到0时实际扣分可能小于规则值。旧自由输入任意加减分接口不再可用，不能用管理员身份无依据调分。

“自动扣分”指核实后按规则自动计算，不是自动判案。处罚应展示理由和申诉入口，通知与关联界面仍需完善。

### 12.2 冲回与恢复

| 方式 | 当前能力 | 后续要求 |
| --- | --- | --- |
| 申诉冲回 reverse_penalty | 已有受控管理员操作，关联已解决申诉，同一处罚只冲回一次 | 明确申诉结论和界面关联；按原实际扣分冲回，保留原审计。 |
| 人工恢复 recover_credit | 满30天清洁期、关联申诉等受控条件下，最多恢复5分；不得超过100 | 清楚展示资格、不合格原因和恢复记录。 |
| 每日自动恢复 | 尚未启用每日任务或资格预览 | 先做预览，明确周期和基准，再配置执行及通知。 |
| 欺诈交易限制解除 | 受控申诉复核；仍有其他有效欺诈处罚时不能解除 | 不因分数回升或时间经过自动解封。 |

恢复和冲回是不同业务：冲回撤销错误处罚，恢复是在规则下逐步改善分数。不能用恢复绕过未解除的欺诈限制，也不能因未核实举报取消清洁期资格。历史缺少基准的账号须先核对，不以空日志直接认定已满30天。

### 12.3 评价与边界验收

评价仅对有效完成订单开放，用户不能给任意陌生人刷交易评价；点赞、收藏与评价不直接当作信用分。测试覆盖59/60/100边界、重复处罚、重复冲回、降分并发发布、冻结卖家库存释放及售后访问；真实运营政策仍须公开。

## 13. 微信支付与正式运营

当前没有真实微信支付、真实托管、真实退款结算或服务收费。模拟订单中的金额仅演示，页面应明确标注，不诱导真实转账到个人账户模拟“平台担保”。

正式阶段需先确认运营主体、微信/支付机构产品准入、交易类目、收款与结算路径、退款资金来源和客服责任；不能保证个人主体具备目标产品资格。真实货款应走具备相应能力的机构方案，不存入自建软件钱包或余额池。
