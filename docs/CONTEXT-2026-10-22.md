## 3. 架构：一套代码，三个运行环境

| 环境 | 入口 | 数据 |
| --- | --- | --- |
| 本地 Python | `Backend mission/server.py` | SQLite（默认）/ MySQL（`HC_DB`） |
| Cloudflare Worker | `worker.py` → `app/cloudflare/` | D1 + R2 + Assets |
| 本地 AI 服务 | `ai_service/server.py`（127.0.0.1:8093） | `ai_service/index.json` 知识库索引 |

Cloudflare 运行时（Pyodide）硬限制：**没有线程、没有持久化 sqlite3、没有 `hashlib.pbkdf2_hmac`**；密码 PBKDF2 600000 轮放浏览器端，服务端只存摘要。

**AI 逻辑有三份实现，改规则必须同步改**：`app/cloudflare/ai_support.py`（线上）、`ai_service/rag.py`（本地服务）、`app/support/service.py` + `app/support/ai.py`（本地后端转发）。

## 4. 数据库三套

- SQLite：删除日志模式（**不用 WAL**）；写事务用 `_WRITE` RLock 串行化（防超卖）。
- MySQL：`HC_DB=mysql://...` 选开；连接必须 `autocommit=True`。
- D1：30+ 张表，`batch()` 是唯一事务原语；`guarded_batch` 做「守卫 SELECT + 写入」。

三处 schema 要同步：`app/core/database.py`、`app/cloudflare/schema.sql`。
**教训：schema.sql 加了表，必须单独在 D1 执行一次 CREATE（`wrangler d1 execute ... --remote`），否则线上 500。**
**备份表清单在 `app/cloudflare/staff_api.py` 的 `BACKUP_TABLES`**，加表必须补，否则备份 503；`tests/test_cloudflare_staff.py` 会静态比对 schema.sql 先报红。

## 7. AI 客服现状（详见 `docs/AI-SUPPORT.md`）

- **模型**：DeepSeek `deepseek-flash`，接口 `https://api.deepseek.com/chat/completions`。
- **路由**：`POST /api/ai/chat`（客户）、`/api/ai/reply`（客服草稿）、`/api/ai/describe` + `/api/ai/price`（发布助手）、`GET/POST /api/admin/ai`、`/api/admin/ai/reload`（本地）。
- **意图分类**（`classify`，三分类）：`human`（明说转人工，在线→转接 / 不在线→留言排队）/ `greeting`（纯问候，剥掉问候词还有内容按业务处理）/ `business`（其余，含投诉与流程咨询）。
- **知识库**：只收 `ai_service/knowledge/faq.md` 的 17 条客户向 FAQ；`ingest.py` 不再收 `docs/*`（曾把内部运维文档喂给客户）。改完跑 `python ai_service/ingest.py` → 重新生成 `app/cloudflare/ai_knowledge.py` → 部署。
- **借鉴的开源设计**（见 `docs/AI-SUPPORT.md` 与日志）：ChatterMate（转人工只认明确请求）、Chatwoot（business hours 留言排队）、FastGPT（没查到就承认+追问）、NVIDIA retail-shopping-assistant（匹配词表从目录派生、k-multiplier 重排、确定性代码覆盖 LLM）、Campus_Marketplace（描述生成/估价）。
- **额度**：`ai_settings`（开关 + 普通 30 次/天、客服 100 次/天）+ `ai_usage`（两次至少间隔 2 秒）；只有真正调用模型才计数。
- **隐私**：问题会发送到 DeepSeek（面板已明示）；内部备注不进提示词；日志只记元数据。

## 8. 前端结构要点

- 全局状态只在 `src/core/state.js`；路由跳转用 `core/nav.js` 的 `go/render`；`router.js` 与 `pages/*` 不许互相 import。
- 事件全部走 `actions/index.js` 分发：点击 → `clicks`，表单提交 → `submits`。**新增按钮必须放 `clicks`**，且 `type="button"`（在表单里）。
- 小转由 `components/ai-pet.js` 的 `mountPet()` 挂到 `body`（登录 + `config.ai` 才挂，后台页也显示，可拖动），跨路由不清空。
- 金额整数分；时间秒级时间戳。
- `market.css` 里 `.ai-assist` / `.ai-price-hint` 是发布页 AI 按钮样式；`ai-pet.css` 管桌宠与面板。

## 9. 必读规则与踩过的坑

1. **路径只从 `app/core/config.py` 取**，不要 `Path(__file__).parent/...`。
2. **工作区可能有并行会话改动**：提交只 add 自己的文件，部署用干净 worktree，快进前先 stash。
3. **本地 Ollama/AI 请求必须绕过系统代理**（否则 127.0.0.1 变 502）。
4. **AI 的 click handler 必须放 `clicks` 不能放 `submits`**；对象里补逗号。
5. **系统 Python 3.8 跑不了并行重构后的代码**（`int | None`），跑测试用 venv。
6. **Windows 上 `nul` 是保留设备名**，普通删除失败，用 `.git/info/exclude` 忽略。
7. **`photos` 不在 products 表里**，在 `data` JSON 中（接口会拍平成顶层字段）。
8. `git merge --ff-only` 被拒 = 有未提交改动会冲突，先 stash 再快进再 pop。
9. 前端 `publish.js` / `support.js` 是单行巨型模板字符串，编辑用精确子串替换。
10. 演示 `var/` 与试用 `var-trial/` 不混用；`var-trial/` 严禁删除。
